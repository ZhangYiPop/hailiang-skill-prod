# 报告模板

本文件定义 `scripts/engine.py` 返回结果后，模型应如何组织自然语言输出。  
所有数字必须来自脚本，模型不得修改、四舍五入或编造。

---

## 一、通用规则

1. **总费用区间**：展示“原币 + 人民币”。  
   例：`约 3.5 - 5.0 万英镑（折合人民币约 32 - 46 万）`
2. **费用明细**：单个国家/单所学校的结果展开为 5 行明细表（项目 / 折合人民币 / 原币），列定义与单位规则见 2.2。
3. **多选国家**：按国家分别展示总费用区间，本轮不展开明细。
4. **追问某国**：把追问涉及的国家重新交给脚本走 `estimate`；返回单国才展开明细，追问多国时不展开。
5. **预算匹配**：只展示符合预算上限的国家；不符合的不展示。预算不足时统一按「是否低于 10 万」分档，见第九节。
6. **兜底话术**：按脚本返回的 `message` 原样输出，不添加数字。
7. **风险说明**：脚本返回 `risk_disclaimer`，放在输出末尾。
8. **地区与专业口径**：结果涉及某国家/地区或某专业方向时，按第十二节补一句当地计费口径。
9. **不展示**：脚本源码、参数、stdin、stdout、stderr、原始 JSON。
10. **禁止未替换的占位符**：最终回复里不得出现 `xx`、`X`、`{}` 这类待替换记号。本文件各节的示例块**只是排版示意**，国家、币种、数字一律替换为脚本返回值。
11. **只输出脚本返回的国家**：用户勾选但 `result.countries` 里没有的国家不补行。部分国家被剔除时脚本会给 `budget_match_message`（见第九节），照原样输出即可，不要自行解释原因或补数字。
12. **样本局限提示**：当某国结果里带 `sample_note`（非 `null`）时，在**该国那一行/那一节后面**补一句脚本给的原文，**不改写、不合并、不重复播报**。同一个提示在多国列表里只对该国说一次；`sample_note` 为 `null` 的国家不要提这件事。该提示只说明样本局限，**不改变任何数字**，不得据此调整金额或暗示「实际可能更高/更低」。
13. **已给的槽位不再进问卷**：挂问卷时只收集**尚未获得**的项。用户在正文里已经给过的信息，不因问卷没勾选而视为缺失；`question_ids` 里不得包含已给项，尤其是用户已说出专业方向时的 `major`。
14. **专业名原样保留**：用户说过的专业词（含口语说法）在回复正文里原样出现，不得改写成大类名。详见第六之二节。

## 二、action = "estimate"（按条件估算）

### 2.1 多选国家（无追问）

**触发条件**：`result.countries` 长度 ≥ 2，且用户未指定具体国家追问。

**输出结构**：

```
💰 预估年度总费用：

- 英国：约 3.5 - 5.0 万英镑（折合人民币约 32 - 46 万）
- 澳大利亚：约 4.0 - 5.5 万澳元（折合人民币约 19 - 27 万）
- 美国：约 5.0 - 7.0 万美元（折合人民币约 34 - 47 万）

{budget_match_message}

{risk_disclaimer}
```

> ⚠️ 上面这段是**排版示意，不是示例数据**。`{budget_match_message}` / `{risk_disclaimer}` 按脚本返回值替换；三行国家示例必须替换为 `result.countries` 的实际内容，未返回的国家不补。

**说明**：
- 每个国家一行。
- 若某国 `currency` 为 `null`，只展示人民币：`约人民币 32 - 46 万`。
- 国家排序按脚本返回顺序（已按人民币总费用下限升序）。
- **只输出脚本返回的国家**：用户勾选但脚本未返回的国家不补行、不猜测数值。
- **样本局限**：某国 `sample_note` 非 `null` 时，在那一行**下面**另起一行写该提示原文（缩进，不与金额同行）。见通用规则 12。

```
💰 预估年度总费用：

- 英国：约 3.5 - 5.0 万英镑（折合人民币约 32 - 46 万）
- 西班牙：约 1.0 - 1.5 万欧元（折合人民币约 8 - 12 万）
  （该国家/地区在此专业方向上库内样本较少，以上区间基于个别院校数据测算，不代表该国该专业方向的整体水平，仅供大致参考。）
- 美国：约 5.0 - 7.0 万美元（折合人民币约 34 - 47 万）
```

### 2.2 单国或追问某国

**触发条件**：`result.countries` 长度为 1（用户只选了一个国家，或追问后只剩一个国家）。

脚本没有独立的 `expand_country` 动作：追问某国时，把追问涉及的国家作为 `countries` 重新调用脚本，仍返回 `action="estimate"`；追问多国时按 2.1 逐国一行、不展开明细。

**输出结构**：

```
💰 预估年度总费用：
- 英国：约 3.5 - 5.0 万英镑（折合人民币约 32 - 46 万）

**费用明细**（分项区间）

| 项目 | 折合人民币 | 原币（单币种时给） |
|---|---|---|
| 学费（{专业}/年） | 约 20.5万–40.4万 元 | 22,400–44,214 GBP |
| 住宿费（/年） | 约 5.3万–10.5万 元 | 5,800–11,450 GBP |
| 生活费（含交通+日常，/年） | 约 4.3万–11.1万 元 | 4,700–12,100 GBP |
| 医疗保险（/年） | 约 7,089 元 | 776 GBP |
| 签证费（办理一次性） | 约 5,097 元 | 558 GBP |

{sample_note}

{budget_match_message}

{risk_disclaimer}
```

**说明**：
- 明细表固定 5 行、顺序不变：学费、住宿费、生活费、医疗保险、签证费。第二列取 `result.countries[0].details_cny`（单位为人民币元），第三列取 `result.countries[0].details_original`（原币数值）。
- **`{sample_note}`**：`result.countries[0].sample_note` 非 `null` 时**原样补一句**（放在明细表之后、`budget_match_message` 之前）；为 `null` 时**整行删掉，不留空行**。见通用规则 12。
- `{专业}` 取本轮 `slots.major`；专业为「不限」时该格写 `学费（各专业/年）`，数值为**统一概括**区间（取该范围内全部有学费数据专业的最小下限～最大上限，不逐专业拆分）。
- **折合人民币列的单位**：医疗保险费、签证费一律用「元」（千分位、取整，如 `约 5,097 元`）；学费、住宿费、生活费用「万」（保留一位小数，如 `约 20.5万–40.4万 元`），但该行上限小于 1 万、或下限为 0 时改用「元」（如 `约 0–31,368 元`）。
- **上下限相等时不写区间**：如 `约 7,089 元`、`约 2.0万 元`。
- **原币列**：写作 `下限–上限 币种`（千分位、取整，如 `22,400–44,214 GBP`）；上下限相等时只写一个数（如 `776 GBP`）；该分项取不到时写 `—`。**不得用人民币反推原币。**

### 2.3 指定学校

**触发条件**：`slots.school_id` 存在，脚本返回单国单校结果。

**输出结构**：

```
💰 {school_name} 本科年度总费用：
- 约 4.7 - 5.0 万英镑（折合人民币约 43.2 - 46.0 万）

**费用明细**（分项区间）

| 项目 | 折合人民币 | 原币（单币种时给） |
|---|---|---|
| 学费（{专业}/年） | 约 30.2万 元 | 33,100 GBP |
| 住宿费（/年） | 约 6.9万 元 | 7,500 GBP |
| 生活费（含交通+日常，/年） | 约 4.9万–7.7万 元 | 5,350–8,400 GBP |
| 医疗保险（/年） | 约 7,089 元 | 776 GBP |
| 签证费（办理一次性） | 约 5,097 元 | 558 GBP |

{budget_match_message}

{替代区域逐行：- {国家}：约 {下限} - {上限} 万人民币}

{risk_disclaimer}
```

**说明**：
- 学校名称、类型、城市可从 `result.countries[0]` 中取。
- 明细表的列定义与单位规则同 2.2。
- 若用户未给专业，脚本先返回 `ask_slot`，模型按追问模板追问。**这不是错误**：
  校名里的专业词（「巴黎理工」「香港教育」「皇家兽医」）**不会**被当成用户选的专业，
  所以「只说校名」一定走追问，不会凭空给一个专业的数字。**不要自行替用户补专业再报数字。**
- 若 `no_tuition = true`，在明细表前增加提示：`库内暂无该方向学费数据，请登录学校官网查看实际开设情况`；该情况下学费行的「折合人民币」「原币」两格都写 `—`。
- `no_tuition = true` 时**不做预算匹配**：脚本 `budget_match_message` 为 `null`、`alternative_countries` 为空（学费按 0 计，与预算比较会失真），模型不要自行补预算判断、也不要补替代区域。
- **该校超预算时（`budget_match_message` 非 `null`）**：先照上面的结构把**该校**的总费用与明细写完（**该校的数字必须出现**，不得因为超预算就不给），再输出 `budget_match_message`；它后面跟着替代区域时，按 §九 的格式逐行列出 `alternative_countries`。两段缺一即为不合格——这正是 §9.2 那条规则的骨架版。
- **替代区域里的数字属于别的国家/地区**：不得写成该校所在国家的费用，也不得说成「符合你的预算」（替代区域按「费用下限 ≤ 预算上限」筛出，**区间上限可以超出预算**）。

### 2.4 全部国家/地区（预算「暂不确定」且未指定国家）

**触发条件**：`slots.budget_undetermined = true` 且未指定国家，脚本返回 `action="estimate"`、`countries` 为全部支持国家/地区（16 个）。

**输出结构**：

```
💰 各国家/地区本科年度总费用：

- 德国：约 0.5 - 1.5 万欧元（折合人民币约 4 - 12 万）
- 马来西亚：约 2.0 - 4.0 万马币（折合人民币约 3 - 7 万）
- …（按脚本返回顺序逐国一行）

{risk_disclaimer}
```

**说明**：
- 逐国一行，不展开明细。
- 该场景不做预算匹配（预算「暂不确定」时脚本不返回 `budget_match_message`）。
- 若某国 `currency` 为 `null`，只展示人民币。

### 2.5 多校对比（一次点名 ≥2 所学校）

**触发条件**：`result.countries` 长度 ≥ 2，且**每一条都带 `school_name`**（脚本一次点了多所学校）。

**输出结构**：

```
💰 预估年度总费用：

- 香港大学：约 32.7 - 40.1 万港币（折合人民币约 28.3 - 34.7 万）
- 墨尔本大学：约 8.6 - 9.2 万澳元（折合人民币约 41.9 - 44.6 万）

{risk_disclaimer}
```

**说明**：

- **两所也好、三所也好，一律不展开明细**——多校对比只逐校给一行总费用区间（与 2.1 多国同一惯例）。
- 排序按脚本返回顺序（人民币总费用下限升序）；**不重排、不排名、不下「哪所更划算」的结论**——要比什么由用户决定。
- 某校 `no_tuition = true`（库内无该方向学费数据）时，在**那一行后面**补一句「库内暂无该方向学费数据，请登录学校官网查看实际开设情况」；该校总额不含学费、会明显偏低。
- 该形态下脚本**有意**不返回 `budget_match_message` 与 `alternative_countries`（用户点名了这几所，就把这几所都给出来；按预算把它们藏起来等于不回答），模型**不要自行补**预算判断、替代区域或「超预算」结论。
- **用户追问其中一所**（如「香港大学呢」）：把该校作为**唯一校名**重新调用脚本，脚本返回单校结果后按 2.3 展开明细。**不要**自己从多校结果里挑一条拆明细（拆分出的数字没有脚本背书）。

## 三、action = "recommend_by_budget"（按预算推荐）

**触发条件**：用户给出预算金额或区间，且未指定国家。

**输出结构**：

```
根据您 {预算描述} 的年度预算，以下国家/地区可能匹配：

- 德国：约 0.5 - 1.5 万欧元（折合人民币约 4 - 12 万）
- 西班牙：约 1.0 - 1.5 万欧元（折合人民币约 8 - 12 万）
  （该国家/地区在此专业方向上库内样本较少，以上区间基于个别院校数据测算，不代表该国该专业方向的整体水平，仅供大致参考。）
- 法国：约 0.8 - 2.0 万欧元（折合人民币约 6 - 16 万）
- 马来西亚：约 2.0 - 4.0 万马币（折合人民币约 3 - 7 万）

{budget_match_message}

{risk_disclaimer}
```

**说明**：
- 预算描述使用用户原话中的金额，如“40 万”“4 万美元”。
- 若 `result.countries` 为空，直接输出 `budget_match_message`。
- 只展示 `total_min_cny <= budget_cap_cny` 的国家。
- 本动作的候选本来就是全部国家/地区，所以「全部不符合」时只会返回低档话术，不会给替代区域（见第九节）。
- **取校口径与 `estimate` 完全一致**：候选校先按专业（及学校类型、城市层级）筛过，因此同一国家同一专业的金额必然与 2.1 / 2.2 相同，两处对不上即为脚本异常。
- **样本局限**：某国 `sample_note` 非 `null` 时，在该国那一行**下面**另起一行补提示原文。见通用规则 12。

## 四、action = "school_not_found"（学校未收录）

**触发条件**：用户指定学校，但学校不在 `schools.json` 中。

**输出结构**：

```
我们暂未收录该校/专业明细，您可了解同类型学校的费用估算情况：

- 英国：约 2.0 - 3.5 万英镑（折合人民币约 18 - 32 万）

{budget_match_message}

{risk_disclaimer}
```

**说明**：
- 第一句固定使用脚本返回的 `result.message`。
- 替代结果按国家聚合、只展示总费用区间，不展开明细。
- 若 `result.countries` 为空（连同类替代都没有），直接输出 `result.message`，不添加数字。
- **同类替代固定两级**（都建立在「国家相同 + 学校类型相同」之上，不引入城市维度），`result.fallback_level` 指出命中的级次：
  1. **第 1 级**：国家相同 + 学校类型相同 + 专业相同；
  2. **第 2 级**：国家相同 + 学校类型相同（不限专业）——第 1 级无结果时放宽，价格按这些院校全部专业取区间。例：美国公立院校普遍没有医学方向学费，点名一所未收录的美国公立院校 + 医学，走的是第 2 级。
- 两级都取不到 → `priority3_msg` 兜底。
- `priority1_hit_msg` 与 `priority2_hit_msg` **文案逐字相同**，脚本用两把键只为区分级次，模型照 `message` 原样输出即可。
- 用户**没有提国家/地区**时，脚本直接返回兜底话术，不做同类替代。
- 用户**没给专业**时，脚本先返回 `ask_slot`，模型按追问模板追问。
- 预算不足时按第九节处理：先输出 `budget_match_message`，再逐行列出 `alternative_countries`。

## 五、action = "school_ambiguous"（学校名歧义）

**触发条件**：学校名匹配到多个。

**输出结构**：

```
你提到的学校可能有多个，请确认一下具体是哪所？

- {candidates[0]}
- {candidates[1]}

确认后我再帮你估算费用。
```

**说明**：
- 候选列表取脚本顶层返回的 `candidates`（半截校名如「加州大学」「伦敦大学」「国王学院」会返回 2-3 个候选校名，已按用户提到的国家缩小范围）。
- `candidates` 为空时，直接问「请提供学校全称」。
- 追问话术取 `message`。该分支的 `message` **顶层和 `result.message` 各有一份、内容相同**
  （历史原因：此分支最早只放在顶层，后续已补 `result.message` 以与其它分支统一，
  顶层副本保留做兼容）。两处取哪个都一样，**不要因为某一层没有就自己编话术**。

## 六、action = "ask_slot"（追问缺失槽位）

**触发条件**：`missing_slot = "major"`。

**固定追问模板**：

```
你想读哪个专业方向？商科 / 文科 / 理科 / 工科 / 医学 / 艺术，或选“不限”。
```

**说明**：
- **`missing_slot` 有且只有一个可能值：`"major"`。** 脚本的 `ask_slot` 分支写死了这一项
  （`decide_action`：`school_id` 或 `countries` 齐了但 `major` 为空才触发）。
  因此**不许按“类似方式”追问任何别的字段**——`school_type`（学校类型）、`city_tier`（城市层级）、
  `budget_range`（预算）**永远不会**出现在缺失项里，出现即是你自己编的，直接违规。
- 追问后等待用户回答，再调用脚本。
- 触发这个追问的常见情形：用户只点了校名（「巴黎理工学院」「麻省理工学院 预算30万-50万」）
  而没说专业。脚本**不会**从校名里的专业词推断专业（见口径说明 7.5），因此专业槽位保持为空。
  此时**只问专业**，不要顺带报费用区间，**更不要顺带问学校类型、城市层级或预算**。

**点名学校时的硬性边界（2026-09-21 新增）**：

用户提到任何一所具体学校（含简称、英文名，如「麻省理工」「MIT」「UCL」）时：

- **本轮必须调用脚本并输出结果。** 学校的类型与所在城市由脚本从库内自解析
  （返回 `result.countries[].school_type`、`result.countries[].city`），**不需要用户告诉你**。
- **禁止**出现「我先确认一下你的学校类型和城市层级偏好，这样能更准确地估算」这类开场——
  这是本轮最常见的翻车方式：脚本明明已返回 `action="estimate"`，模型却自己把这一轮变成追问。
- **禁止**在回复里列出「学校类型（公立/私立/无偏好）」「城市层级（一线/二三线/无偏好）」选项。
- 唯一允许的追问仍是 `missing_slot = "major"`（用户点了学校但通篇没提专业）。
- 正确示范：用户说「麻省理工读工科一年要多少」→ 直接出数，正文可以顺带交代
  「麻省理工属于私立院校，位于美国剑桥市」——这句是**脚本返回值**，不是问句。

**前置条件（硬性）**：这段追问**只在用户通篇没有提过任何专业信息时才允许出现**。

- 用户说过任何具体专业词——包括不在问卷六个选项里的口语说法（金融、会计、建筑、临床、传媒、电气……）——
  **一律不得再问专业**。此时即使脚本返回 `missing_slot = "major"`，
  也要把用户说过的那个词**原样**作为 `major` 再交一次脚本，而不是当成缺失项去追问。
- **自检**：回复里即将出现「你想读哪个专业方向」这句时，先回看**全部历史轮次**。
  用户说过任何专业词 → 这句话不许出现。
- 判据不是「这个词在不在问卷的六个标签里」，而是「用户有没有说出一个专业」。**你不需要自己换算大类。**

**不得追问预算（硬性）**：

- 脚本返回里带 `budget_known` 字段。**`budget_known = true` 时，本轮绝不能问预算。**
- 用户给过**具体金额**（「一年25万」「预算20万」）或给过**档位**（「20万-30万」「50万以上」）
  都算给过了。档位是开放式的（如「50万以上」）也算。
- 问过的槽位不许再问——**预算也是槽位**。

## 六之二、专业名保真（必读）

**为什么这条重要**：本技能的槽位由平台从**对话历史**里解析，并且**优先采信最近一轮**的值。
你在回复正文里写的字，会成为后续解析槽位的依据。

**必须做到的**：

1. **用户说过的专业词，在你每一轮回复的正文里都原样保留。**
   用户说「金融」→ 你写「金融」；用户说「建筑」→ 你写「建筑」。
   不替换为「商科」「工科」等大类名，也不只写问卷标签。
2. **已给专业时，问卷不得再包含 `major` 这一题。**
   问卷只用来收集还没有的项；把已知项再问一遍，等于给用户一个覆盖自己原话的机会。
3. **传给脚本的专业维度也要保真。** 把用户原话原样作为 `major` 交给脚本，
   **不要自己先归一成大类别名再传**。

**为什么要保真（真实缺陷，2026-09-21 线上会话）**：

会话里用户第 1 轮说「新加坡和美国读**金融**」，助手也正确复述了「金融」，
但挂出的问卷里**仍然带着专业这一题**。用户随后照问卷标签回了「**商科**」，
平台解析槽位时取了最近一轮的「商科」——用户原话「金融」就永久丢失了。

这一次金额恰好没错（金融本就属商科）。但同样的路径换成：

| 用户原话 | 库内大类 | 用户可能照标签选成 | 后果 |
|---|---|---|---|
| 建筑 | **工科** | 艺术 | **金额算错** |
| 临床医学 | 医学 | 理科 | **金额算错** |
| 传媒 | **文科** | 艺术 | **金额算错** |

即：**助手给出的选项列表会诱导用户改口，而系统最终采信的是用户改口后的值。**
所以「不要改写专业名」不是措辞偏好，而是**正确性要求**。

**第二层原因：不要让模型替引擎判定大类。**
脚本入口内置专业词表，识别能力远强于按问卷 6 个标签去猜。
一旦你把用户原话归成了大类名再传给脚本，**脚本就没有机会用它的词表**，
只能采信你的判断——猜错就静默算错钱。实测：

| 用户原话 | 你（或平台）可能传的 | 脚本自己会判的 |
|---|---|---|
| 建筑 | 艺术 ❌ | 工科 ✅ |
| 传媒 | 工科 ❌ | 文科 ✅ |

脚本会自己处理不一致：它一旦发现自己判出的类别与你传的不同，就用**用户原话**的判定，
并在结果里标 `major_conflict`。**以脚本结果为准，不要据你的判断去改数字。**

**归一大类由 `scripts/engine.py` 在入口完成**，模型不需要判断、不需要换算、也不要在正文里解释大类归属。

## 七、action = "show_form"（展示问卷）

**触发条件**：无国家、无学校、无预算。

**输出结构**：

```
好的，我来帮你测算本科留学的年度费用。请先填写以下信息：
```

然后平台自动展示问卷（`assets/questionnaire.json` 定义的 5 个字段：国家/地区、专业方向、学校类型、城市层级、预算范围；预算具体金额不入问卷，只从用户自然语言识别）。

**「目标留学国家/地区」的末项 `暂不确定`（2026-09-21 起）**：

- 语义 = **所有收录国家/地区（16 个）各算一遍**，不是「跳过这一题」。
- 提交后脚本走 `action="estimate"`、`countries` 返回全部 16 国，**报告格式同 §2.4**：逐国一行、不展开明细。
- **不要**因为用户选了这一项就追问「那你具体想去哪」——这正是选项存在的意义。
- 与 §2.4 的差别只在触发来源：§2.4 是「预算暂不确定 + 未指定国家」，这里是「国家明确选了暂不确定」。两者的输出结构完全一致，可复用同一段模板。

## 八、action = "reject"（超范围或无结果）

**触发条件**：超范围问题（`reason="out_of_scope"`），或筛选后无匹配学校。

**输出结构**：

```
{result.message}

{risk_disclaimer}
```

**说明**：
- `reason="out_of_scope"`（学段护栏命中硕士/博士/MBA/预科/语言班/高中及以下等，且全文未出现「本科」）：**只输出 `result.message`**，不给数字、不带风险说明。
- `reason="unsupported_region"`（命中范围外地区，如中国澳门）：**只输出 `result.message`**，不给数字、不带风险说明。话术为：
  > 该地区暂时不在收录范围内，可点击页面底部“找机构/课程”按钮，联系相关机构进行咨询。
- `reason="no_school_match"`（表单路径按条件一所院校都没筛出来；**用户没有点名学校**）：只输出 `result.message` 后接 `risk_disclaimer`。话术为：
  > 按当前条件没有匹配到院校。可以放宽学校类型、城市层级或调整专业方向后再来估算。
- 其他 reject（筛选后无匹配学校）：输出 `result.message` 后接 `risk_disclaimer`。
- 若 `result.message` 为空，使用固定兜底：  
  `我们暂未收录该校/专业明细，您可以点击页面底部“找机构/课程”按钮，联系相关机构了解更多信息。`
- 不给任何数字。
- **注意区分**：`no_school_match` 是「条件太窄」不是「学校没收录」，**不要**套用「我们暂未收录该校/专业明细」那句（用户根本没提学校）。
- **专业全称已归类，正常不会再误触本分支**（2026-09-21 起）：平台把用户选的专业全称（`金融` / `计算机` / `临床医学`）放进 `major` 槽位时，脚本会先归入六大类再筛选（口径说明 §7.6）。此前 `金融` 这类词会裸透出、查不到任何学费行，误触本分支回「按当前条件没有匹配到院校」——遇到「用户明明说了专业却答没有匹配」，先按该节排查，**不要**用本分支话术敷衍。

## 九、预算匹配消息（budget_match_message）

脚本可能返回以下消息之一，模型直接输出，放在总费用区间之后、风险说明之前。

| 场景 | 消息 | 是否带替代区域 |
|---|---|---|
| 有匹配国家 | 以下是与您的需求较为匹配的部分国家/地区。 | 否 |
| 部分国家被剔除 | 其余地区（{国家列表}）按当前条件估算的总费用超出了你的年度预算，本次未展开。其总费用区间为：{总费用区间}。 | 否 |
| 预算匹配 | 您的预算达到/覆盖总花费区间，预算匹配度较高。如需进一步了解情况，可点击页面底部“找机构/课程”按钮，联系相关机构进行咨询。 | 否 |
| 预算不足（上限 <10 万） | 该预算目前较难覆盖海外本科的常规开销，建议可考虑中外合作办学、国内院校国际项目等升学渠道，或降低城市层级/调整目标地区后再来估算。 | 否 |
| 预算不足（上限 ≥10 万） | 根据你的年度预算，还可以关注这些区域： | 是，接 `result.alternative_countries` |
| 所问地区**全部**被剔除（上限 ≥10 万） | 你提到的地区（{国家列表}）按当前条件估算的总费用超出了你的年度预算，本次未展开。其总费用区间为：{总费用区间}。根据你的年度预算，还可以关注这些区域： | 是，接 `result.alternative_countries` |

**分档规则（所有路径统一）**：预算不足时只按预算上限是否低于 10 万人民币分两档——

- 上限 < 10 万：输出低档话术，不给数字、不给替代区域。
- 上限 ≥ 10 万：先输出以冒号结尾的那句，再逐行列出 `result.alternative_countries`（忽略用户原本选定的国家/学校，保留专业、学校类型、城市层级条件，取人民币总费用下限 ≤ 预算上限的国家/地区，按下限降序、最多 5 个——脚本已排好序并截断，照原样列出即可）。
- **所问地区一个都没留下时**，话术前面会先补出它们各自的总费用区间（形如 `你提到的地区（英国）按当前条件估算的总费用超出了你的年度预算，本次未展开。其总费用区间为：英国 约 31.3 - 63.1 万人民币。`），再接以冒号结尾的那句。**照原样输出**——不要重算、不要改成「未收录」、不要只留后半句：用户至少要知道**自己所问的地区要多少钱**，否则只看到一堆别的国家。
- **点名学校单校路径（2.3）仍只用后半句**：该校的费用就写在正文里，不必复述。
- `alternative_countries` 为空时脚本会改返回低档话术，因此不会出现「冒号后面没有内容」。
- **「部分国家被剔除」**：用户勾了多国、只有一部分留存在 `result.countries` 时，脚本返回上面那条话术（`{国家列表}` 与 `{总费用区间}` **两个占位符都由脚本填好，顺序也已排定**——按费用下限降序，超出预算最多的在前，与留存国家的升序不同），照原样输出。**话术里的区间就是被剔除国家的总费用区间——不要重算、不要改写、不要重排序、不要自行解释原因，也不要再补其他国家的数字。**
- **未被剔除时不再输出「部分国家/地区」前缀**：筛选后没有国家被剔除（展示的就是全部符合预算的国家）时，`budget_match_message` 为 `null`，不要自行补上 `以下是与您的需求较为匹配的部分国家/地区。`

**替代区域的输出格式**：

```
根据你的年度预算，还可以关注这些区域：

- 马来西亚：约 5.3 - 10.0 万人民币
- 德国：约 4.0 - 9.0 万人民币

{risk_disclaimer}
```

**替代区域的硬规则**（输出格式不稳的根因就在缺这几条，逐条照做）：

1. **只写折算人民币区间**，形如 `约 {下限} - {上限} 万人民币`（保留一位小数）。**不写原币、不写币种名**——脚本返回的替代区域条目里也只有国家与人民币区间，没有原币可写。
2. **上下限相等时只写一个数**：`约 5.3 万人民币`。
3. **条数 = 脚本返回的条数**（脚本最多给 5 条），逐条列全：不截断、不合并、不补行、不留空行。
4. **顺序 = 脚本返回的顺序**（人民币总费用下限降序，最接近预算上限的排在第一个）：不重排、不分组。
5. **不展开明细**：每行只有「国家 + 区间」两段，不得补学费/住宿/生活费等分项。
6. **不加自造标题或括注**（如「（符合 20万-30万 预算）」）：这一句问的是话术，标题只有一个——`根据你的年度预算，还可以关注这些区域：`。
7. **不得说成「符合你的预算」**：替代区域按「**费用下限** ≤ 预算上限」筛出，所以**区间上限可以超出预算**（§3.2 筛选规则：符合的国家展示完整区间、允许上限超预算）。说成「符合预算」与数字自相矛盾。
8. **不得把这些数字写到用户所问的国家名下**（见 9.1）。

### 9.1 用户点名国家 + 全部不匹配（禁止张冠李戴）

当用户**明确问了某几个国家**，而脚本返回 `result.countries` 为空、只有 `result.alternative_countries`：

| 允许 | 禁止 |
|---|---|
| 说明「这两国按当前预算都够不上，本次不展开明细」 | 把 `alternative_countries` 里的数字写成用户所问国家的费用 |
| 问是否要放宽预算，或是否要看符合预算的其它地区 | 给用户所问的每个国家填同一个数字 |
| 放宽后**重新调用脚本**再给数字 | 声称「两国费用相近」——除非脚本返回的就是那样 |

`alternative_countries` 里的数字属于**别的国家**。把它写到用户问的国家名下，等于给了一个错误答案。

**根源提醒**：`alternative_countries` 与 `result.countries` 用的是不同条件（前者忽略用户选的国家）。
两者数值不可互换。

### 9.2 数值与国家对拷（输出前自检）

- 每一行的国家名与费用**必须来自同一条记录**，不得跨记录拼装。
- 输出前核对：**任两国的区间不得完全相同**——除非脚本返回的确实完全相同（照实输出）。
- 自检来源是脚本返回值本身；不要凭印象补数。

- 替代区域只展示国家/地区 + 总费用区间，不展开明细。
- 点名学校且超预算时：先按 2.3 展示该校总费用与明细，再输出 `budget_match_message` + 替代区域；若该校 `no_tuition = true`（学费缺失，不是「超预算」问题），则整段不输出，见 2.3 说明。

> 备注：`config.json` 的 `budget_match.sufficient`（预算充足）与 `budget_match.undetermined_no_tuition`（无学费无法比较）两条话术当前**不会**被脚本返回，启用方式待定；模型不要等待它们出现。
>
> 另外，点名学校且 `no_tuition = true` 时脚本**有意**不返回任何预算话术（`budget_match_message` 为 `null`）——学费缺失时「预算匹配度」无从判断，正对应 `undetermined_no_tuition` 那句文案的口径。

## 十、样本局限提示（sample_note）

结果里某国的候选院校只有 **1 所**时，脚本在该国结果上带 `matched_schools` 与 `sample_note`，用来提示"这个区间来自单点样本，不代表该国该方向整体水平"。

| 字段 | 位置 | 说明 |
|---|---|---|
| `matched_schools` | `result.countries[i]` | 该国该专业方向命中的院校数（**仅供判断，不展示给用户**） |
| `sample_note` | `result.countries[i]` 与 `result.sample_note` | 提示原文；样本充足时为 `null` |

**播报规则**：

1. `sample_note` 为 `null` → **完全不提这件事**，不要写"样本充足"之类的话。
2. 非 `null` → **原样输出脚本给的句子**，不改写、不缩短、不补充解释。
3. 多国列表里**逐国判断**：只有触发的那些国家才带提示，每个国家只带一次。
4. 位置：单国/明细场景放在明细表之后、`budget_match_message` 之前；多国列表场景紧贴该国那一行（下一行缩进）。
5. **不得据此调整数字或暗示方向**——不写"实际可能更高"、"建议以官方为准所以可能超出"之类。它只说明样本局限。
6. 与第十二节「地区与专业口径」是**两回事**：那条讲当地怎么计费，这条讲样本够不够，两句可以同时出现。

**当前触发范围**（库内固定 12 组，样本=1 所）：

| 国家/地区 | 专业方向 |
|---|---|
| 俄罗斯 | 医学、艺术 |
| 意大利 | 文科、商科 |
| 法国 | 文科、医学 |
| 瑞士 | 文科、工科 |
| 西班牙 | 文科、理科、工科、商科 |

> 门槛由 `assets/config.json` 的 `sample_note.threshold` 控制（当前为 `1`），改这个值即可调整触发范围；上表随数据变化会浮动，不要写死进话术。

## 十二、地区与专业口径

结果里出现某国家/地区或某专业方向时，按 `assets/region_notes.json` 取对应条目，在风险说明之前补一句当地计费口径：

| 条目 | 何时用 | 例 |
|---|---|---|
| `countries.<国家>.note` | 结果出现该国家/地区（全学科成立的口径） | 德国公立免学费、瑞士学费按学期计 |
| `countries.<国家>.by_major.<专业>` | 结果命中该国家 + 该专业方向 | 韩国医学不招国际生、日本医学入学金另缴 |
| `zones.<专业>` | 结果命中医学 / 艺术方向 | 北美 MD/DDS/DVM 为本科后专业学位 |

**说明**：

- 只播报结果实际命中的国家/方向，没命中的不播报。
- 取不到对应条目就不补充，不自行编造。
- 播报位置：总费用区间（含明细）之后、风险说明之前。
