# 口径说明与边界

本文件说明留学费用计算器的业务边界、计算口径、数据规则和兜底逻辑。  
供模型组织话术和开发者维护脚本使用。

---

## 一、业务边界

### 1.1 支持范围

- **仅限本科阶段**的海外留学费用粗略估算。
- 支持国家/地区（16 个）：美国、英国、澳大利亚、加拿大、新加坡、中国香港、日本、韩国、马来西亚、新西兰、德国、法国、意大利、瑞士、西班牙、俄罗斯。（中国澳门不在收录范围，理由见 1.2）
- 支持专业方向：文科、理科、工科、商科、医学、艺术。
- 支持学校类型：公立、私立、无偏好。选「无偏好」= 不筛学校类型，公立私立全部纳入（取极端范围）。
- 支持城市层级：一线、二三线、无偏好。选「无偏好」= 不筛城市层级，全部城市纳入（取极端范围）。
- 支持预算范围：10万以下、10万-20万、20万-30万、30万-50万、50万以上、暂不确定（写法与 `config.json` 的 `budget_bands`、`questionnaire.json` 的选项 value 一致）。
- 预算具体金额：问卷不收集（问卷只给档位），只从用户自然语言（「预算 40 万」「家里一年 20 万」「4 万美元够吗」）或显式 `budget_amount` 槽位（单位：万元）识别。

### 1.2 不支持范围

以下情况**不给数字**，直接说明范围并兜底：

- 硕士、博士、MBA、研究生文凭
- 预科、国际大一、语言班、桥梁课程
- 高中及以下留学
- 非学历课程
- 深入的收入讨论、投资回报、奖学金细节
- 精确到具体项目的学费报价

兜底话术（`config.json` 的 `fallback.out_of_scope_msg`，脚本原样返回）：

> 我目前只支持进行本科阶段的留学费用粗略估算，硕士/预科/语言班等不在范围内。您可以了解本科相关费用，或点击页面底部“找机构/课程”按钮，联系相关机构进行咨询。

**引擎侧学段护栏**：`scripts/engine.py` 会先做一遍学段拦截——命中下列关键词且全文未出现「本科」时，直接返回 `action="reject"`、`reason="out_of_scope"`，只给兜底话术，**不给数字、不带风险说明**：

- 学段词：硕士、博士、研究生、MBA、预科、国际大一、语言班、桥梁课程、大专、专科、专升本、非学历、成人教育、postgraduate、master、PhD（英文词按词边界匹配，`McMaster University` 不会被 `master` 误伤）
- 低龄留学短语：高中留学、初中留学、小学留学、中学留学、低龄留学、出国读高中、出国读初中、去国外读高中、申请高中、高中及以下、初高中留学
- 低龄留学组合：K12 学段词（高中/初中/小学/中学）+ 留学意图（留学/出国/申请/就读/费用/学费/多少钱/预科）或前置意图词（想/要/去/读/申请/打算/准备…）。**只描述身份不算**——「高二学生，高中在读」不拦，因为参数里同时会出现「本科」或没有留学意图。

**引擎侧范围外地区护栏**：`config.json` 的 `fallback.unsupported_regions` 列出库内不收录的地区别名（中国澳门 / 澳门 / 澳門 / Macao / Macau）。命中后直接返回 `action="reject"`、`reason="unsupported_region"`，只给 `fallback.unsupported_region_msg`，**不给数字、不带风险说明**：

> 该地区暂时不在收录范围内，可点击页面底部“找机构/课程”按钮，联系相关机构进行咨询。

原因：澳门大学、澳门科技大学本科不招收内地非高考生，该地区已整体移出学校库与问卷（学校、学费、住宿、城市生活费、签证、汇率六处一并移除）。学段护栏优先于本条——「澳门大学硕士多少钱」按 `out_of_scope` 处理。

一旦出现「本科」字样即视为在范围内，不拦（例如「本科的费用，不是硕士」）。

## 二、费用计算口径

### 2.1 总费用构成

```
年度总费用 =
  学费
+ 住宿费
+ 生活费
+ 医疗保险费
+ 签证费
```

> 与旧口径「……+ 签证及医疗费」完全等价：把原来的合并项拆成两项分别计，总额逐国不变。医疗保险费按年、取区间；签证费为办理一次性费用、取单值。

### 2.2 学费

- 来源：`tuition.json`
- 按 `school_id` + `major_category` 取 `tuition_min`、`tuition_max`。
- 表内**没有**该 (学校, 专业) 组合的行 = 该校未开设该专业方向，按「该校不提供该专业」处理（表内不出现 `null` 学费，原 130 条空值行已于 2026-09-20 删除）。
- 多所学校时：取所有符合条件学校 `tuition_min` 的最小值、`tuition_max` 的最大值。
- 用户选“不限”专业时，**统一概括**：取该范围内全部有数据专业的区间并集（`tuition_min` 的最小值 ～ `tuition_max` 的最大值），不逐专业拆分；明细表学费行标签写 `学费（各专业/年）`。该口径对多校聚合（按国家）与单所学校一致。

### 2.3 住宿费

- 来源：`accommodation.json`
- 按 `school_id` 取 `accommodation_fee_min`、`accommodation_fee_max`。
- 多所学校时：取所有符合条件学校的最小值、最大值。

### 2.4 生活费

- 来源：`city_living.json`
- 按 `country` + `city` 取 `cost_min`、`cost_max`。
- 包含交通费和日常开销，不含签证、住宿、医疗保险。
- 多所城市时：取所有符合条件城市的最小值、最大值。
- **城市缺失回退**：
  1. 同国家 + 同城市
  2. 同国家 + 同城市层级
  3. 同国家所有城市
  4. 兜底：不给数字

### 2.5 「符合条件学校」的统一定义（**所有计费路径必须一致**）

> 2.2 学费、2.3 住宿费、2.4 生活费里反复出现的「符合条件学校」，指的是**同一个集合**：
> `filter_schools()` 的输出——即按用户已确认的**国家 + 专业（+ 学校类型 + 城市层级）**筛过之后的院校。
>
> **四项分项必须共用这个集合**。若学费按专业筛了、住宿费/生活费却拿"有任意专业学费"的全量院校来算，
> 就会出现同一国家同一专业在两条入口算出两个数——实测「意大利 · 文科」被米兰新美术学院（只有艺术专业）
> 的高价住宿抬到 19.0 万，而追问路径给的是 13.5 万。

**历史缺陷（2026-09-21 修复）**：`handle_recommend_by_budget`（按预算推荐）当时未调 `filter_schools()`，
直接取"有任意专业学费"的全部院校；全量扫描 16 国 × 6 专业 = 96 组里 **66 组**与其他入口不一致
（最大偏差：法国·文科 +7.8 万、澳大利亚·文科 +6.5 万、英国·工科 +6.3 万）。
修复后 `recommend_by_budget` 与 `estimate` 走同一套取校逻辑，96 组**全部一致**。

**回归约束**：两条入口对「同一国家 + 同一专业」必须返回**逐值相同**的 `total_min_cny` / `total_max_cny`。
这是硬不变量，任何新入口的加入都要满足。

### 2.6 医疗保险费与签证费

- 来源：`visa_medical.json`
- 按 `country` 取三项：`visa_fee`（办理一次性、单值）、`medical_insurance_min` / `medical_insurance_max`（按年、区间）
- **两项分别计、分别展示**：
  - 医疗保险费：`medical_insurance_min` ~ `medical_insurance_max`
  - 签证费：`visa_fee`
- 计入年度总费用时再相加：`签证及医疗费合计 = visa_fee + medical_insurance_min` 到 `visa_fee + medical_insurance_max`，与拆前的合并口径逐国相等。
- 明细表两行的原币值直接取表内原币，不做汇率反推。
- 收录范围覆盖全部 16 个支持国家/地区（与 `fx.json` 一致），无缺失，因此不做「暂未收录」兜底；国家无记录时该项按 0 计。

### 2.7 多币种与汇率

- 来源：`fx.json`
- 核心换算系数：`cny_per_unit`（1 单位外币 = 多少人民币）
- 所有内部计算先换算成人民币，再做预算匹配。
- 原币展示（总费用行）：取该国出现次数最多的学费币种；若混币种，只展示人民币。
- 原币展示（明细表原币列）：由 `details_original` 逐分项给出，取表内原币值、不折算反推；某分项混用多币种时该格为 `null`，模型写 `—`。
- 汇率固定为 2026-09-08 CFETS 中间价，不动态更新。
- 输出中不说明“按某日汇率估算”，但风险说明中可带日期。

## 三、预算匹配口径

### 3.1 预算上限确定

| 用户输入 | 预算上限 |
|---|---|
| 具体金额（如 40 万） | 40 万人民币 |
| 具体金额（如 4 万美元） | 4 万 × 汇率，换算为人民币 |
| 区间 10万-20万 | 20 万 |
| 区间 30万-50万 | 50 万 |
| 50万以上 + 无金额 | 无上限 |
| 50万以上 + 有金额 | 用户输入金额 |
| 暂不确定 | 不做预算匹配；若同时未指定国家，输出全部支持国家/地区的费用区间（不展开明细） |

问卷只提供档位（`budget_range`），不再收集具体金额；具体金额仅来自用户自然语言或显式 `budget_amount` 槽位，**金额优先于档位上限**。

「预算 20 万-30 万」这类区间表达按档位取上限（30 万），不会因为句中出现了单个数字而降成 20 万。

**本轮档位 vs 历史金额（2026-09-21 修，重要）**：

预算金额的扫描一律**先看本轮、再看历史**，且**本轮档位优先于历史金额**。判定顺序：

1. 本轮有显式 `budget_amount` 槽位 → 用槽位值。
2. 本轮用户原话里能扫出预算金额（需带预算意图词）→ 用该金额。
3. 本轮拿到了档位（`budget_range` 可解析、且不是「暂不确定」）→ **按档位定上限，历史金额作废**。
4. 以上都没有，历史对话里扫到过金额 → 用历史金额（`budget_from_history = true`）。
5. 都没有 → 无上限。

**为什么必须让本轮档位压过历史金额**：修复前 `_slot_text()` 把**全部历史用户消息**拼成一串，
第 1 轮说过的「一年 25 万」每一轮都会被重新扫到，`budget_cap_cny` 被永久钉死在 250000。
后果是用户后来说的「**50 万以上**」完全失效——实测 `budget_range` 已正确解析为「50万以上」，
但 `budget_cap_cny` 仍是 250000，`countries` 恒为空、每次都给替代地区，**用户放宽预算的动作等于没发生**。

**`budget_known`（预算是否已知）**：只要本轮或历史里出现过预算信息（具体金额 / 档位 / 暂不确定）即为 `true`。
它决定**表单还能不能再问「年度预算」**——见 3.4。

### 3.2 筛选规则

```
人民币总费用下限 <= 预算上限
```

- 符合的国家展示完整区间，允许上限超出预算。
- 不符合的国家不展示。
- **部分国家被剔除时**（有留存、也有被剔除）→ `budget_match_message` 返回固定话术 `budget_match.partial_dropped_msg`，脚本替换两个占位符：`{countries}` = 被剔除国家的名字（顿号连接），`{ranges}` = 被剔除地区的总费用区间（**人民币万元**，形如 `约 42.6 - 75.9 万人民币`，多国以「；」连接）：`其余地区（英国、美国）按当前条件估算的总费用超出了你的年度预算，本次未展开。其总费用区间为：英国 约 31.3 - 63.1 万人民币；美国 约 42.6 - 75.9 万人民币。`
  - **不新增字段（Q2=B）**：话术与区间同在一句里，仍只走 `budget_match_message`；被剔除的国家名与区间都只在话术里出现。
  - **最多列 5 个**：被剔除超过 5 个时，按人民币总费用下限**降序**取**前 5 个**（即超出预算最多的那几个），`{countries}` 末尾加「等」，`{ranges}` 只列这 5 个；被截掉的是最接近预算的那几个。实测「按预算推荐」路径一次可剔除 8 个，不设上限会变成大段罗列。
  - **区间用人民币而非原币**：与「预算」同币种，用户能直接看出超了多少；也避免韩元这类大额原币不便阅读。
  - **未剔除任何国家时不说话**：筛选后一个都没被剔除（展示的就是全部符合预算的国家）时，`budget_match_message` 为 `null`；此时不应输出「以下是与您的需求较为匹配的部分国家/地区。」——一个都没剔除就不存在「部分」，只勾一国时尤其明显。
- 全部不符合时统一分档（**阈值 10 万人民币，所有路径同一套逻辑**）：
  - 上限 < 10 万 → 输出 `budget_match.insufficient_low`（低档话术），不给替代区域。
  - 上限 ≥ 10 万 → 输出 `budget_match.insufficient_high_prefix`（以冒号结尾），并在 `result.alternative_countries` 返回符合预算的替代国家/地区。
  - **所问地区一个都没留下时，话术里补出它们各自的总费用区间**（第三十二次 ④-a α）：走 `budget_match.all_dropped_msg`，形如 `你提到的地区（英国）按当前条件估算的总费用超出了你的年度预算，本次未展开。其总费用区间为：英国 约 31.3 - 63.1 万人民币。根据你的年度预算，还可以关注这些区域：`——话术与区间同句、**仍只走 `budget_match_message` 一个字段**（不新增字段，与 `partial_dropped_msg` 同构）；超过 5 个时按人民币下限降序取前 5 个并加「等」。为什么必须补：修复前一个都不匹配时 `apply_budget_filter()` 直接 `return [], msg, alternatives`，被点名地区的费用被整段丢掉——用户只看到「还可以关注这些区域」，**从头到尾不知道自己所问的地区要多少钱**。`partial_dropped_msg` 早就补了区间，同一条诉求漏了这条。
  - **点名学校单校路径不补**：该校的费用已写在正文里（报告模板 §2.3），复述是噪音。补不补由调用方决定——`budget_shortfall_message(slots, cap, dropped_results=None)` 的第 3 个参数就是「被丢弃的那些结果」，`apply_budget_filter()` 会传，单校路径不传。
  - **例外：点名学校且 `no_tuition = true`**（该校在该专业方向上表内无学费记录，学费按 0 计）→ 整个预算匹配不执行：`budget_match_message` 为 `null`、`alternative_countries` 为空。学费缺失时总额被低估，匹配结论不可信（实测曾出现「埃克塞特 · 艺术 12.2–14.8 万」配上「预算匹配度较高」的自相矛盾）。
- **替代区域口径**：忽略用户原本选定的国家/学校，保留专业、学校类型、城市层级条件，从全部支持国家/地区中取 `人民币总费用下限 <= 预算上限` 的，按人民币下限降序取前 5 个；替代区域为空时回落到低档话术（因此「冒号后面为空」不会出现）。
  - **为什么改成「降序 + 前 5 个」**（第三十三次）：线上一次返回 **14 个**替代地区（rev_ab70a2e…，马来西亚 4.9 万 → 新加坡 29.7 万，升序），逐条罗列把风险说明与导流话术顶出视野；升序还会让「明显够得着」的便宜地区占满名额。改为降序后露出的是最接近预算上限的 5 个（预算 20-30 万时 = 新加坡 / 澳大利亚 / 加拿大 / 中国香港 / 瑞士），截掉的是最便宜的几个。上限由引擎常量 `ALTERNATIVE_DISPLAY_LIMIT = 5` 定。
  - **条目只保留「国家 + 人民币总费用区间」**（第三十二次 ④-b）：引擎侧由 `_slim_alternative()` 收敛（`ALT_KEYS = country / total_min_cny / total_max_cny`），`currency` / `total_min_original` / `total_max_original` / `details_cny` / `details_original` **不再返回**。两条理由：① 替代区域一律只输出折算人民币区间、不展开明细（原币本就不进输出）；② 那两个明细键占失败返回体的 **58.5%（4375/7476 字符）**，而线上模型曾据此写出「31,428 - 59,738 林吉特」这类原币错配。
  - **多校对比路径不做预算剔除**（见 4.5）：`budget_match_message` 恒为 `null`、`alternative_countries` 恒为空。
- 「按预算推荐」（用户未指定国家）的候选本身就是全部国家/地区，因此该路径全部不符合时只会走低档话术。

### 3.4 预算已给过 → 表单不得再问「年度预算」（`budget_known`）

**需求（2026-09-21 用户拍板）**：用户只要在会话里给过预算——具体金额（「一年 25 万」）或档位
（「20万-30万」「50万以上」「暂不确定」都算）——**后续表单一律不带「年度预算」这一题**。

**引擎侧实现**：`main()` 的 `ask_slot` 分支返回新增两个字段：

| 字段 | 含义 |
|---|---|
| `budget_known` | 预算是否已知（本轮或历史出现过预算信息） |
| `askable_slots` | 本轮**允许**追问的槽位白名单；`budget_known = true` 时**不含** `budget_range` |

- `budget_known = true` → `askable_slots = []`（预算不要再问）。
- `budget_known = false` → `askable_slots = ["budget_range"]`。

**为什么这题特别容易踩**：「暂不确定」也是有效回答，但它在 `BAND_CAP` 里 `min/max` 都是 `null`，
早期实现据此算出 `budget_cap_cny = None`、把 `budget_known` 判成 `false`，于是**用户明明回过了「暂不确定」还被再问一遍**。
现在 `budget_known` 的判定显式包含 `or slots["budget_range"]`。

**提示词侧配套**：SKILL.md 输出红线已写明「**追问由脚本决定**——没返回 `ask_slot` 就不追问、
只问它给的缺失项、不问预算」；`## 三、action 契约` 的 `ask_slot` 一行也标了
「`budget_known = true` 时**绝不问预算**」。两处要一起改，缺一处就漏。

### 3.5 问卷只有 2 个必答项 → 点名学校不得追问城市/院校类型

**需求（2026-09-21 用户拍板）**：用户点名了具体学校，必须直接出结果，**不得**再问「城市层级」「学校类型」。

**事故现场**（平台真实会话 `revision_test_dbg_975ee196…`，2 轮）：

| 轮 | 用户 | 脚本 | 模型回复 |
|---|---|---|---|
| 1 | 麻省理工读工科一年要多少 | **未调用** | 「我先确认一下你的学校类型和城市层级偏好，这样能更准确地估算年度费用。」← 翻车 |
| 2 | 我要去麻省理工 这所学校，你不能判断它是什么类型吗 | `success`，`action="estimate"` | 正确出数（美国 约 91,995–99,095 USD） |

**根因（两层，主因在第一层）**：

1. **`assets/questionnaire.json` 的必填标记错了。** 本分支把 5 题全写成 `required: true`；
   而线上在架包只有 `countries`、`major` 是 `true`，`school_type` / `city_tier` / `budget` 都是 `false`。
   模型读到「5 题全必填」就理解成「必须收齐 5 项才回答」，于是即使引擎已经给了 `estimate`，
   它仍然按问卷把题补问一遍。这正是历史上反复记录的那条教训：
   **「形式（表单/自然语言）不是病根，『必填标记 + 无轮次上限』才是」**。
   本次修法：`school_type` / `city_tier` / `budget_range` 三题改 `required: false`
   （文件 sha `7453cfccb2355361` → `647f6cba935a962b`，仅三处 true→false，行尾保持 pure-LF）。
2. **模型第一轮没调脚本。** 引擎侧其实完全正确——`decide_action()` 里 `school_id` 有值时
   只在 `major` 为空才 `ask_slot`，否则直接 `estimate`；`ask_slot` 的 `missing_slot`
   **写死只有 `"major"`**，永远不会返回 `school_type` / `city_tier`。
   实测矩阵（`tmp_in/probe_school_case.py`）：

   | 输入 | 引擎 action | 追问项 |
   |---|---|---|
   | 麻省理工读工科一年要多少 | `estimate`（school_id 1046） | — |
   | 麻省理工一年要多少 | `ask_slot` | **仅 major** |
   | 麻省理工读工科一年要多少 预算30万 | `estimate` | — |
   | 学校+专业经平台 `parameters` 传入 | `estimate` | — |

   **没有任何一条路径会追问城市或学校类型**。所以这是提示词/配置问题，不是引擎 bug。

**提示词侧配套（本次同步改）**：

- `SKILL.md` 输出红线写明「**点名学校 = 直接出数**，绝不追问城市或院校类型」，并说明
  「学校类型与城市由脚本从库内自解析，用户不需要提供」。
- 同一条约束在 `## 三、action 契约`（「点名学校 = 直接出数」）与
  `## 二、唯一动作：先调脚本`（「本轮只要出现任何与留学费用相关的用户输入，第一件事就是调用脚本」）两处都有落点。
  > ⚠️ **引用纪律**：此处原按编号引 SKILL.md 的「核心原则第 10 条」「`### 必须调用脚本的场景` 第 3 条」
  > 等小节，SKILL.md 改版后这些编号已重排、小节已合并，引用集体失效。
  > **references 一律不再按编号引用 SKILL.md，改为内联原文。**
- `references/报告模板.md` §六 删掉「若 `missing_slot` 为其他字段，按类似方式追问」这句**漏洞条款**
  （它等于邀请模型自造字段），改为「`missing_slot` 有且只有一个可能值 `major`」。
- `references/数据字典.md` §九 的必填表由「全「是」」改为「country/major 是，其余否」。

### 3.3 排序

`result.countries` 按人民币总费用下限升序；下限相同按上限升序。

**两处例外，方向相反**：`result.alternative_countries` 按下限**降序**取前 5 个（第三十三次）；被剔除地区话术里的 `{countries}` / `{ranges}` 同样按下限**降序**取前 5 个（第二十八 / 三十二次）。两处共用同一条直觉——「离预算上限最近（或被超出最多）的排前面」。

## 四、学校匹配口径

### 4.1 指定学校存在

- 按 `name_zh`、`name_en`、`aliases` 匹配（英文/长名不区分大小写；4 字以内的短别名区分大小写）。
- 落在国家/地区别名内部的命中不算数（防止学校短别名被国名吞掉）；当前库内已无此类互撞，规则作为防御保留。
- 匹配到唯一学校 → 正常计算。
- 匹配到多个 → `action="school_ambiguous"`，追问确认。
- **半截校名**（「伦敦大学」「加州大学」「国王学院」「英国伦敦大学」）：先剥离动词前缀（想读/去/申请…），再逐字去掉开头做「名称包含片段」匹配（「英国伦敦大学」第 3 轮命中「伦敦大学」）；唯一候选 → 直接按该校计算，多候选 → `action="school_ambiguous"` 并在 `candidates` 返回候选校名（已按用户提到的国家缩小范围）。

### 4.2 指定学校不存在

同类替代固定**两级**（都建立在「国家相同 + 学校类型相同」之上，不引入城市维度）：

1. **第 1 级**：国家相同 + 学校类型相同 + 专业相同
2. **第 2 级**：国家相同 + 学校类型相同（不限专业）——第 1 级无结果时放宽，价格按这些院校全部专业取区间

脚本用 `result.fallback_level`（1 / 2）说明命中的级次；两级都取不到 → 兜底话术。

最前面加：

> 我们暂未收录该校/专业明细，您可了解同类型学校的费用估算情况：

若两级都没有：

> 我们暂未收录该校/专业明细，您可以点击页面底部“找机构/课程”按钮，联系相关机构了解更多信息。

补充：

- 用户**没有提国家/地区**时，脚本不进入两级替代，直接返回兜底话术。
- `similar_school_fallback.priority1_hit_msg` 与 `priority2_hit_msg` 文案逐字相同，只为区分级次而保留两把键。

### 4.3 表单路径按条件一所不剩

表单路径（用户没点名学校）经 `filter_schools` 筛选后一所院校都不剩时，返回 `action="reject"`、**`reason="no_school_match"`**，`result.message` 为 `fallback.no_school_match_msg`：

> 按当前条件没有匹配到院校。可以放宽学校类型、城市层级或调整专业方向后再来估算。

- **不复用 4.2 的「我们暂未收录该校/专业明细…」**：那句的前提是「用户点名了一所学校、库内没有」，而这里用户根本没提学校，用错了会误导。
- 话术落在 `config.json` 的 `fallback.no_school_match_msg`，与 `similar_school_fallback.priority3_msg` 是两把不同的键、两套文案。

### 4.4 平台已解好「学校」槽位：`school` / `schools`（第三十二次）

平台 planner 会把学校解析成结构化槽位再传进来：单校用 `school`，多校用 `schools`（数组）。
引擎侧由 `_explicit_school_ids()` 读取（`SCHOOL_SLOT_KEYS = school / schools / school_name / school_names`），
值可以是中文名、英文名、别名，也可以是含校名的一句话。

- **为什么必须读它**：第三十一次诊断实测，港大会话里平台给过 `school: "香港大学"` 与
  `schools: ["香港大学","墨尔本大学"]`，而旧引擎里字面量 `"school"` 出现的次数是 **0** ——
  它只扫文本。槽位里已经给了结构，就不该再靠文本猜（文本里校名会被国名区间屏蔽、被长短校名互抢）。
- **解析不出来的值直接丢掉**，不据此判 `school_not_found`：那是文本扫描路径的职责；
  槽位里塞了脏值时应当**退回**文本路径，而不是把用户可见的失败结论甩出去。
- 优先级：**平台槽位 > 本轮文本 > 历史文本**（见 4.5 第 5 条）。

### 4.5 多校并列 / 对比（`resolve_school_slots`，第三十二次）

`resolve_school_slots(payload, current_text, joined)` 返回 `(school_ids, mode)`，
`mode ∈ none / single / compare / ambiguous`：

| 顺序 | 条件 | 结论 |
|---|---|---|
| 1 | 平台显式给了 ≥2 所 | `compare`——平台结构优先，不看文本里有没有连词 |
| 2 | 候选 0 所 | `none`（交给半截校名匹配 `match_school_partial()`） |
| 3 | 候选 1 所 | `single` |
| 4 | 候选 ≥2 所，且**本轮**文本含并列 / 比较连词 | `compare`，一所都不丢 |
| 5 | 候选 ≥2 所、本轮恰好 1 所（无连词） | `single` —— **本轮优先于历史** |
| 6 | 候选 ≥2 所、本轮 ≥2 所（无连词） | `ambiguous`，让用户确认 |
| 7 | 候选 ≥2 所、本轮 0 所（只有历史） | `ambiguous` |

**并列 / 比较连词**（`SCHOOL_COMPARE_TOKENS`）：和 / 与 / 跟 / 、/ 以及 / 及 / 还是 / 对比 / 比较 / 哪个 / 哪所 / 哪家 / 谁 / vs。
**只认本轮的连词**：历史里的「A 和 B」不该让本轮追问单校时又变成对比。

**多校对比的工程口径**（`_estimate_multi_school()`）：

- `result.countries` 逐校一条，每条带 `school_name` / `school_type` / `city`；按人民币总费用下限升序。
- **不展开明细**（报告模板 §2.5）。用户追问其中一所时，该校成为本轮唯一校名，走单校路径自动展开明细。
- **不做预算剔除**：`budget_match_message` 恒为 `null`、`alternative_countries` 恒为空。
  用户点名了这几所就把这几所都给出来——按预算把用户点名的学校藏起来，与「点名学校 = 直接出数」冲突，
  也正是第三十次线上事故的回退形态（该校数字被丢弃、模型手里没有可播的内容）。
- 结果字段集合与其它 `estimate` 路径**完全一致**（仍是 `countries` / `alternative_countries` /
  `budget_match_message` / `sample_note` / `risk_disclaimer` 五个），不新增字段；形态靠
  「每条是否带 `school_name`」区分。

**不得静默丢弃（R-a）**：旧 `match_school()` 只保留「与最长名等长」的候选，实测
「香港大学和墨尔本大学」的候选里只剩墨尔本大学（短一些的整所被吞）、
「香港大学和香港中文大学」甚至直接按香港中文大学出了数。现在：

- 候选 = 命中的**全部**学校（`school_hits()` 每校只出一条记录，长度取该校命中的最长名字）。
- 噪音改由**区间包含关系**排除（`_drop_nested_hits()`）：短别名落在另一所校内名区间之内时，
  不算第二所学校——`UBC` 撞巴塞罗那大学的 `UB`、`UCLA` 撞伦敦大学学院的 `UCL`、
  `HKU` 撞高丽大学的 `KU`、`NYU` 撞延世大学的 `YU`…
  这类噪音此前被「只留最长名」顺手挡住，但那同一个过滤器也会把**真实的**第二所学校挡掉，
  两件事必须分开处理。
- **副产物**：11 个缩写别名（UBC / UCLA / NYU / TUM / CAU / HYU / VUW / UWO / UWA / BUW / HKU，
  另加东京大学的「东京大」）修复前被误判成「歧义」，现在能唯一命中。全量 1162 条
  「校名 × 中文名 / 英文名 / 别名」对照：1150 条两版都对、**12 条旧错新对**、**0 条反向回归**、0 条两版都错。

**本轮优先于历史（R-b）**：`joined` = 本轮 + 历史，而平台每轮都会把完整用户历史注入 payload。
只看 `joined` 会被历史校名的长名支配掉本轮校名（实测：历史「墨尔本大学」+ 本轮「香港大学呢」
→ 判成歧义、候选里只剩墨尔本，**用户点名的香港大学被丢**）。因此候选合并按
**平台槽位 > 本轮文本 > 历史文本**，且在无连词时只采信本轮文本。

## 五、样本局限提示（`sample_note`）

某国某专业方向在库内只命中 **1 所**院校时，那个区间就是单点样本，容易被读成「该国该专业的整体水平」。
因此在该国结果上附带提示，把话说清楚。

**字段**：

| 字段 | 位置 | 值 |
|---|---|---|
| `matched_schools` | `result.countries[i]` | 该国该方向命中的院校数（整数） |
| `sample_note` | `result.countries[i]`、`result.sample_note` | 触发时给提示原文，否则 `null` |
| `sample_note.threshold` | `assets/config.json` | 触发门槛，当前为 `1`（即「命中数 ≤ 1」时触发） |

**触发范围（当前数据，96 组里 12 组）**：

| 国家/地区 | 专业方向 |
|---|---|
| 俄罗斯 | 医学、艺术 |
| 意大利 | 文科、商科 |
| 法国 | 文科、医学 |
| 瑞士 | 文科、工科 |
| 西班牙 | 文科、理科、工科、商科 |

**边界**：

- 只做提示，**不改任何数字**，也不影响预算匹配与排序。
- `matched_schools == 0` 走的是 4.3 的 `no_school_match`，不走这里。
- 点名学校路径不触发（本来就是单校），字段恒为 `null`。
- 播报规则见 `报告模板.md` §十。
- 双入口一致：`estimate` 与 `recommend_by_budget` 都按同一门槛判定同一批数据。

## 六、专业处理

- 用户指定专业 → 映射到 `major_category`。
- 用户选“不限” → 取所有有 `tuition` 记录的专业。
- 表内没有该 (学校, 专业) 组合的行 → 视为该校未开设该专业方向。表单路径下 `filter_schools` 会因此把该校从候选里筛掉；**点名学校路径不做这层筛选**（见下方注意）。
- `config.json` 中 `dims.no_major_tuition` 包含医学、艺术，仅作为提示，不参与计算。
- 注意：**`no_tuition = true` 只可能出现在「点名学校」这条路径上**，表单路径不可达。实测口径（2026-09-20）：表单路径 16 国 × 6 专业 = 96 组**全为 0 命中**（唯一例外「马来西亚 + 艺术」一所不剩，直接 `action="reject"`）；点名学校路径 166 校 × 6 专业 = 996 组里 **422 组命中**，含义是「用户点名的学校在该专业方向上表内无记录」＝该校未开设该方向，学费按 0 计、住宿/生活费/签证照算，总额会明显偏低，务必按报告模板 §2.3 加提示。（删空值行前后逐条比对过 96 + 996 组返回，**完全一致**：删除只是把「未开设」的表示方式统一，不改变任何返回值。）；该路径上 `no_tuition = true` 时脚本**同时不返回任何预算话术与替代区域**（`budget_match_message = null`），避免与报告模板 §2.3 的「库内暂无该方向学费数据」提示自相矛盾。

## 七、上下文解析

脚本从 stdin 读取 JSON。解析分**两条通道**，优先级从高到低：

### 7.1 结构化槽位优先（命中即锁）

平台表单 / planner 会把用户选好的值直接放在 JSON 里，这些值**直接采信**，该维度不再做全文扫描：

- 顶层键：`countries` / `major` / `school_type` / `city_tier` / `budget_range`。
- 同样的内容还可能出现在 `parameters` / `planner_parameters` / `facts` / `slots` / `form` / `values` 层，按固定顺序补充，同一维度**先命中的层胜出**。
- 值的写法会被规整到库内规范值：`any` / `all` / `无偏好` → `不限`（专业）或 `无偏好`（学校类型 / 城市层级）；`computer science` / `engineering` → `工科` 之类按别名表映射。**英文变体按词边界匹配、长词优先**，避免 `science` 抢走 `computer science`、`art` 抢走 `liberal arts`、`cs` 落进 `economics`。
- **国家（`countries`）多一道「未指定识别」**：值里出现「暂不确定 / 不确定 / 还没确定 / 未确定 / 待定」一律视为**未指定国家**，等价于不传该键（详见 7.7）。
- **专业（`major`）多一道「大类归属回退」**：别名表只覆盖 6 个规范值 + 少量英文写法，平台若直接把用户选的专业全称（`金融` / `计算机` / `临床医学` / `视觉传达设计`）放进槽位，规整后仍不在六大类内，就再用 `major_keywords` 的归属表把它归回六大类。详见 7.6。
- **专业（`major`）从 2026-09-21 起改为「脚本判定优先」**：平台给的 `major` 槽位只是**候选**，
脚本仍会对本轮文本做一次专业识别（脚本内置专业词表）；**扫到的具体专业压过 planner 给的大类标签**。
即 planner 传 `major=艺术`、用户原话是「建筑」→ 最终按**工科**算（`major_source = "scanned_over_explicit"`），
并在返回值里带 `major_conflict = {"explicit": "艺术", "scanned": "工科"}` 供排查。详见 7.8。
- 命中即锁：某个维度一旦从结构化槽位拿到值，**不再对该维度做任何全文扫描**。

### 7.2 全文扫描（仅在结构化槽位缺该维度时）

- 用 `country_aliases` 匹配国家。**命中必须整体落在「非国别语境」区间之外**（第三十五次）：
  该区间 = 专业词（`major_keywords` 全量）∪ 货币单位（港币 / 美元 / 澳元 / 日元…）∪ 单字别名他义词表。
  否则美国含的单字别名「美」会把「美术」「美学」「完美」判成美国，中国香港含的「港」会把
  「港币」「港口」「港股」判成中国香港。与 `school_name_spans()` 同一套区间哲学：不删别名，只把落在区间里的命中排除。
  - 用 `major_keywords` 匹配专业。**命中必须落在校名区间之外**（见 7.5），
    并按 7.5 的「意图词窗口优先」决定位置。
- 用 `schools.json` 的 `name_zh/name_en/aliases` 匹配学校。
- 用正则匹配预算金额，支持人民币和外币；**要求数字前后出现预算意图词**（预算/家里/家里一年/最多/不超过/控制在…，或 够/够不够/可以吗…），避免把助手历史回复里的费用区间（「折合人民币约 32 - 46 万」）误当成用户预算；显式 `budget_amount` 槽位优先，按其单位万元换算（>500 视为元）。
- 用关键词匹配学校类型、城市层级、预算区间（「无偏好」= 不筛）。

### 7.3 扫描文本分「本轮」与「历史」两段（`_slot_text_split`）

扫描文本由 `SLOT_TEXT_KEYS`（`query` / `用户消息` / `user_message` / `用户原话` / `message`）下的字符串，
加上 `messages` / `recent_messages` 里 **`role == "user"`** 的 `content` 拼成。
**2026-09-21 起这段文本被拆成两截**，用途不同：

| | `current_text`（本轮） | `history_text`（历史） |
|---|---|---|
| 组成 | `SLOT_TEXT_KEYS` 的值 + `messages` 里**最后一条** user 消息 | `messages` 里**更早的** user 消息 |
| 供什么槽位 | 除预算外的全部维度 | **仅**预算金额兜底 |
| 预算 | 优先采信 | 只在本轮完全没预算信息时才用（见 3.1 第 4 步） |

**为什么必须拆**：拆之前 `_slot_text()` 把 `messages` / `recent_messages` 里**所有** user 内容拼成一整串，
于是历史每一轮都被反复重扫。实测线上会话 `rev_646c933e...`：第 1 轮的「一年 25 万」把
`budget_amount_cny = 250000` 永久钉死，第 6 轮用户说「50万以上」也压不动它。
**历史文本只留给「本轮什么都没说、但以前说过金额」这一种兜底场景**——多轮对话里金额确实只说过一次，
完全丢掉会丢信息；但绝不能让它反过来覆盖本轮明确给出的档位。

**为什么助手历史必须排除**：本技能的追问会列全套枚举选项（「商科 / 文科 / 理科 / …」「公立 / 私立 / …」
「一线 / 二三线 / …」）。这些清单一旦进入扫描文本，「先命中先赢」的扫描顺序会让清单里的**首项**顶掉用户真正的选择——
实测平台真实请求中，用户选的是文科 / 私立 / 二三线，却因助手追问被误判为商科 / 公立 / 一线，费用算到了另一个国家上。

- 结构化槽位能拿到值时，这条风险被 7.1 完全挡住（这才是表单路径的正解）。
- 只有助手历史、**没有任何结构化槽位**时，仍会按旧逻辑扫描（已知局限）。传请求时应优先带上显式槽位。
- 兜底：完全取不到用户原话时才回落到「递归摊平全部文本」（`_deep_collect`）。
- `payload.user_query` 若存在且不在 `current_text` 里，会**补进本轮**（平台另一种传参形态）。
### 7.4 其它

- 学段护栏与范围外地区护栏先跑（见 1.2）：命中即直接兜底，不再解析其它槽位。
- 半截校名按 4.1 处理。

### 7.5 专业识别的两条护栏（校名屏蔽 + 意图词优先）

专业关键词是**全文扫描**的，而不少校名本身就含专业词——「巴黎**理工**学院」「香港**教育**大学」
「伦敦**政治经济学**院」「马来西亚**理科**大学」「皇家**兽医**医学院」。旧逻辑「先命中先赢」完全
不看位置，于是校名里的专业词会顶掉用户明说的专业。实测点名学校路径 166 校 × 6 专业 = 996 组里，
**36 组**（3.6%）判成这样，例如「巴黎理工学院 想读医学」被算成工科、「伦敦政治经济学院 想读文科」
被算成商科。两条护栏同时上：

**0. 别名表本身要干净：短别名不做跨实体子串匹配（2026-09-21）**

护栏再密，也拦不住**别名表自己写错**。实测「香港科技大学」曾把 `科大` 收作别名，于是：

- 「商**科大**概多少钱」→ 命中 `科大` → 判成**点名香港科技大学** → 静默只返港科大 1 国 1 条。
- 「文**科大**概多少钱」「工**科大**概多少钱」「想去澳洲读商**科大**概多少钱」同理，全部中招。
- 危险点在于**这是静默给错答案**，不是拒答：用户问「商科多少钱」，拿到的是港科大一条数据，看不出错。

修法是**从源头去掉这个别名**：`科大` 在中国大陆语境指向中国科学技术大学（合肥），
本库未收录该校，因此不该把 `科大` 挂在任何港校名下。保留 `港科大` / `香港科技大学` / `HKUST`。

**通用判据（新增别名前先问）**：这个别名是否是「常见语素」？把它拆开是不是会落进别的词的内部？
凡长度 ≤ 3 且由高频汉字组成（`科大` `理大` `中大` `国大` `南大` `西大` `高丽大`…）的别名，
一律要有**地域 / 校名前缀**（`港科大` `港理大`）或**大写字母缩写**（`HKUST`），裸短词不收。

**A. 校名区间屏蔽（`school_name_spans`）**

- 先把文本里所有「校名 / `name_zh` / `name_en` / `aliases`」的字符区间算出来。
- 专业关键词的命中区间若**完全落在**某个校名区间内，**不算命中**。
- 与 4.x 里 `country_alias_spans` 屏蔽国名内短别名是同一套做法：不删关键词，只把「落在别人名字里」的命中排除。
- 短名（4 字及以内，含 `MIT` 这类英文缩写）保持大小写敏感，避免小写化后误命中普通单词。

**B. 意图词窗口优先（`find_major_in_text`）**

- 用户明说专业时通常带意图词：`MAJOR_INTENT_WORDS` = 想读 / 要读 / 想学 / 要学 / 报考 / 申请 / 专业是 / 专业方向 / 方向是 / 读的是 / 学的是；
  另有组合式 `MAJOR_INTENT_PAIRS` = 「读…专业」「学…专业」「读…方向」「学…方向」（中间最多 3 个非标点字符）。
- 先在意图词之后的 `MAJOR_INTENT_WINDOW`（10 字）窗口里找专业词；命中即作为候选。
- 窗口内没有，再退回**全文扫描**（**仍带 A 的屏蔽**）。
- 意图窗口候选与全文候选**一起按位置竞争，取最靠前的一处**——窗口结果不是无条件胜出。

**C. 同位置并列长词优先（第三十五次）**

- 专业词命中先按**位置**排序，位置相同时按**词长降序**——与 `_major_attr_fallback()` 的长词优先对齐。
- 判据是 `sort(key=lambda x: (x[0], -len(x[2])))`，`_major_scan_first()` 与 `find_major_in_text()` 两处同改。
- 修前只按位置排，并列时靠 `MAJOR_KEYWORDS` 的字典顺序（商→文→理→工→医→艺）决出，**短词恒胜**：
  实测 16 组对照组里 6 组错——`生物医学工程`→理科（应工科）、`生物制药`→理科（应医学）、
  `化学工程与工艺`→理科（应工科）、`人文地理`→文科（应理科）、`播音与主持艺术`→文科（应艺术）、
  `纺织品设计`→工科（应艺术）。**反证**：`_major_attr_fallback("生物医学工程") = 工科`
  ⇒ 同一条输入在「槽位路径」与「文本路径」上给出两个答案，本身就是实现不一致。
- 改动后同 16 组全部归位；779 组「想读\<词\>」+ 779 组裸词全量复算，差异恰好 31 条，**全部是上述误判的修正，零回退**。

**为什么意图词表刻意不含裸「学」「读」**：`医学` `数学` `科学` 里的「学」会被当成意图词，
反而在专业词**之后**开出一个假窗口，把「医学，巴黎理工学院」这种句式的结论又拉回校名里的专业词。
要表达「读XX」用上面的组合式，不要放裸字。

**副作用与收益**：

- 收益：上述 36 组误判**全部归零**（996 组复算：旧 36 → 新 0，逐条核对 36 组全为修正、0 回退）；
  「major 之外」的槽位零变化，对照组（专业词不在校名里的正常提问）零变化。
- 副作用（**这是一个修正，不是回退**）：「只说校名、没说专业」的提问（如「巴黎理工学院」「麻省理工学院 预算30万-50万」）
  旧逻辑会从校名里猜一个专业（`巴黎理工学院` → 工科）并直接给数字；新逻辑不再猜，
  `slots.major` 留空、`decide_action` 落到既有分支返回 `action="ask_slot"` + `missing_slot="major"`，
  由模型按报告模板 §六 追问专业。这条 `ask_slot` 分支本来就在 `decide_action` 里（`school_id` 有而 `major` 为空即触发），
  旧逻辑只是被「猜出来的专业」绕过了它。

**验证口径**：996 组「\<校名\> 想读\<专业\>」全量复算 + 6238 组多句式回归（专业在前 / 组合式意图词 / 无意图词裸词 /
只说校名 / 校名+预算档 / 国+专业），差异全部落在预先声明的桶里，意外差异 = 0。

风险：可能误匹配否定句（如“我不想去美国”）。当前接受该风险，后续可通过否定词优化。

### 7.6 专业大类归属回退（`_major_slot_value`）

**问题（2026-09-21 线上真实会话）**：用户「去新加坡和美国读金融 哪个便宜」→ 平台把专业全称
`金融` 直接放进 `major` 槽位 → `_norm_slot_choice` 的别名表只认 6 个规范值 + 少量英文写法，
中文全称认不出来 → 走到函数第 4 步兜底 **原样透出** `slots["major"] = "金融"` →
`filter_schools` 用 `(school_id, "金融")` 查 `TUITION_BY_KEY` **全部落空** →
`action="reject"`、`reason="no_school_match"`，回「按当前条件没有匹配到院校」。
用户明明说清了专业，反而拿不到结果；同一句话把专业换成「商科」就正常出数——**这是同一需求的两种命运**。

**影响面（实测）**：`major_keywords` 共 **781** 个词条（同一写法重复 2 处，去重后 779），旧逻辑里只有 **97** 个能归入六大类，
**674 个（87.4%）**在走「显式槽位」路径时会裸透出。也就是平台只要传专业全称，
大多数情况都会掉进 `no_school_match`。注意这与 7.5 的「校名屏蔽 / 意图词优先」是**两条不同路径**：
7.5 管的是「没有结构化槽位时的全文扫描」，本节管的是「平台已给出 `major` 槽位」——后者优先级更高（7.1 命中即锁），
所以 7.5 的护栏**拦不住**这个 bug。

**修法（`_major_attr_table` / `_major_attr_flat` / `_major_attr_fallback` / `_major_slot_value`）**：

- `major` 槽位的规整统一走 `_major_slot_value(raw, majors)`：先走原有别名表；
  **结果已在六大类内或为 `不限` 时立即返回，不做任何改动**；只有「未归类」才进归属回退。
- 归属表把 `major_keywords` 反过来用：`词 -> 大类`（只收 `dims.majors` 里的大类）。
- 回退两档，**长词优先**（避免 `医学` 抢走 `临床医学`、`工程` 抢走 `软件工程`）：
  1) 整串精确（大小写 / 空格归一）
  2) 子串包含
- `不限` 是槽位哨兵值，**不参与回退**；空值返回 `None`。
- 认不出来的自由文本（「我还没想好」）**保持原样**，不强行猜一个大类——即保持旧行为，
  只是这种输入本来也不该出现在槽位里。

**`_norm_slot_choice` 本身没有改动**：它还服务 `school_type` / `city_tier` / `budget_range`，
把回退逻辑内联进去会波及那三个维度。本节只新增了一个 `major` 专用入口。

**验证口径（2026-09-21）**：

- 781 个专业词 × 「是否归入六大类」：**781 / 781**，漏 0（旧 97 / 781）。
  归属表去重后 779 条，重复的两处是文科内的「媒介」与文科/工科同现的 `communication`。
- 双引擎分桶回归 **2650** 组：相同 1299 / MISFIX 1351 / **其它差异 0**。
  其中 996 组「\<校名\> 想读\<专业\>」与 1092 组表单路径**逐例不变**（7.5 成果与表单行为零破坏）。
- 零副作用对照包（只把 `engine.py` 换回备份、其余 15 个文件逐字节取当前包）跑 **1553** 组：
  差异 1349 个，**100% 落在 MISFIX 桶**，OTHER = 0。

**与 7.8 的关系**：本节解决「槽位里是全称但引擎认不出」，7.8 解决「槽位里是 planner 给的大类、
而用户原话里有更具体的专业」。两者相邻但不同层：本节在**别名表**上加归属回退，
7.8 在**优先级**上让全文扫描压过槽位。

### 7.7 国家「未指定」的识别（`_norm_slot_countries`）

问卷「目标留学国家/地区」新增选项「暂不确定」，语义 = **所有收录国家/地区各算一遍**（不额外加说明话术）。
为了让这个语义在引擎里成立，`countries` 槽位单独走一个入口函数 `_norm_slot_countries(values)`：

- 逐个值规整；命中 `COUNTRY_UNDETERMINED_TOKENS`（`暂不确定` / `不确定` / `还没确定` / `未确定` / `待定`）→
  标记「未指定」，该值**不进**国家列表。
- 其余值按 `country_aliases` 归一到规范国名，去重后返回。
- **只要出现过「未指定」标记，整体返回空列表** `[]`。

**三种写法完全等价**（实测逐字段相同）：

| 输入 | `slots.countries` | `estimate` 返回国家数 |
|---|---|---|
| `["暂不确定"]`（新选项） | `[]` | 16 |
| `[]`（空数组） | `[]` | 16 |
| 不传 `countries` 键 | `[]` | 16 |

**混选整体归零**：`["美国", "暂不确定"]` → `[]` → 16 国全算。
理由：「暂不确定」的语义与「点名某个国家」互斥；若只保留具体国家，等于用户说了「都可能」却被砍成 1 国，
**范围被静默收窄**比放宽更危险。这里选择放宽。

**为什么要「整体归零」而不是「遇到未指定就跳过、保留其余」**：同一维度里的值来自同一次表单提交，
「暂不确定」出现在同一份选择里说明用户并未锁定范围，此时任何收窄都是替用户做决定。

**不受影响**：具体国家（`["美国"]` → 1 国）、多国（`["美国","英国"]` → 2 国）、空值 / null 一律照旧。

**与 7.1「命中即锁」的关系**：空结果视为「该维度未命中」，继续往下一层容器找（可能有更具体的值）；
若所有层都拿不到，才回落到 7.2 的全文扫描。这样「平台偶尔把选项清单一起塞进槽位」时不会误伤。

**问卷侧配套**：`assets/questionnaire.json` 的 `countries.options` 末尾新增
`{ "value": "暂不确定", "label": "暂不确定" }`，同时 `max_selections` 由 16 调为 **17**
（否则 17 个选项配 16 的上限自相矛盾）。

### 7.8 专业判定优先级：脚本扫描 > planner 标签（`major_source` / `major_conflict`）

**问题（2026-09-21 线上会话 `rev_646c933e...`）**：用户第 7 轮问「新加坡**建筑**一年多少钱」，
planner 传 `--major 工科`。旧逻辑里「结构化槽位命中即锁」（7.1）会**整段跳过全文扫描**，
引擎内置的专业词表根本没有机会介入 —— 专业最终归哪一类，完全由 planner 的粗标签决定。
同类风险：用户说「临床」被标成「理科」、说「传媒」被标成「艺术」。

**2026-09-22 口径复核（第三十六次）**：`建筑` 属**工科**（工学·建筑类），已由艺术归位。
归位前词表把 `建筑` 归在艺术，该会话经「扫描优先」拿到的其实是**艺术**口径 ——
与 planner 传的 `工科` 相比，算错方向的是**词表那一侧**。归位后两者一致（`工科`、无 conflict），
本节机制的价值改由下列仍成立的情形体现：临床 → 理科、传媒 → 艺术（见 7.9 反例表）。

**为什么 planner 不可信**：planner 只看得到 `prompt_markdown`（= SKILL.md），**读不到 `references/`**
（见 7.9），它的专业标签是把用户原话粗略塞进六大类的产物，**粒度天然比脚本内置的专业词表粗**。
而脚本自己有权威词表（`config.major_keywords`，脚本内置专业词表；匹配两档：**整串精确 → 子串包含**，长词优先），没理由让粗标签赢。

**新判定链（`extract_slots` 内）**：

```
scanned = find_major_in_text(joined, school_mask)   # 本轮文本的专业识别（含校名屏蔽）
explicit = 平台给的 major 槽位

explicit 有值 且 scanned 无值      -> 用 explicit，major_source = "explicit"
explicit 有值 且 scanned == explicit -> 用 explicit，major_source = "explicit"
explicit 有值 且 scanned != explicit -> 用 scanned， major_source = "scanned_over_explicit"
                                        + 记 major_conflict = {explicit, scanned}
explicit 无值 且 scanned 有值      -> 用 scanned， major_source = "scanned"
```

**「不限」哨兵：本轮的「不限」优先于历史扫描出的任何专业（第三十五次）**

`scanned_major` 的取值顺序 = **本轮的「不限」> 扫描出的专业 > 历史的「不限」**。

| 情形 | 旧行为 | 新行为 |
|---|---|---|
| 第 1 轮「英国商科」+ 第 2 轮「改成不限」 | `major = 商科`（历史里的专业被扫出来，压过本轮） | `major = 不限` |
| 本轮「专业不限」/「不限专业」 | `major = 商科`（同上） | `major = 不限` |
| 本轮「预算不限」（说的是钱，不是专业） | `major = 不限`（**误把预算当专业**） | 维持扫描结果 / `None`，**不动专业** |
| 历史说过「专业不限」、本轮未提专业 | `major = 不限` | `major = 不限`（承接，优先级最低） |

- 判据只看「不限」的**左右各 2 字**：出现预算语境词（预算 / 费用 / 花销 / 开销 / 金额 / 学费 / 成本）
  → 判为「预算不限」，不算专业哨兵；否则一律算（`_is_major_unlimited`）。
- 窗口刻意取小：放大到 6 字会把「费用不限，但专业想读商科」里真正该生效的信息也误判掉。
- **为什么历史里的「不限」仍要承接**：若只认本轮，用户早轮说过「专业不限」、之后只补国家，
  `major` 会退回 `None`，`decide_action` 又会追问一次专业——正是「已给信息又问一遍」。
- **与「历史金额压过本轮档位」是同一类病**：预算通道早已区分本轮/历史，专业通道当时漏了。

**三个字段**（`slots` 内，仅排查用，不影响计费）：

| 字段 | 取值 | 含义 |
|---|---|---|
| `major_source` | `explicit` / `scanned` / `scanned_over_explicit` | 专业最终是谁定的 |
| `major_conflict` | `null` 或 `{"explicit":…, "scanned":…}` | 仅在两值不一致时出现 |

**实测（2026-09-22 复测，第三十六次）**：

| 输入 | 结果 | `major_source` |
|---|---|---|
| 「建筑」+ `--major 艺术` | **工科** | `scanned_over_explicit`（含 conflict） |
| 「建筑」+ `--major 工科` | 工科 | `explicit`（无 conflict） |
| 「商科」+ `--major 商科` | 商科 | `explicit` |
| 「计算机」+ `--major 工科` | 工科 | `explicit` |

**为什么不让 `major_conflict` 走用户可见文本**：用户不关心是谁定的专业，
真实专业名已按输出红线「**专业名原样保真**」保留在正文里，`major_conflict` 只服务线上排查。

**与 7.6 的关系**：见 7.6 末尾。

### 7.9 槽位来源：平台从**对话历史**解析，且优先采信最近一轮（**平台机制，非本技能可控**）

**背景（2026-09-21 线上会话 `rev_5d1bca80...`，用户报障「金融没有映射到商科」）**：

用户第 1 轮说「新加坡和美国读**金融**，那个便宜点」。助手也正确复述了「金融」（专业识别没问题）。
但助手挂出的问卷里**仍然带着专业这一题**；用户照问卷标签回了「**商科**」。
平台最终传给脚本的槽位是 `major=商科`——**用户原话「金融」永久丢失**。

**引擎是无辜的**。实测：`norm_major('金融') = 商科`；走完整 stdin 通道时
`major=金融` 与 `major=商科` 的 `total_min_cny/total_max_cny` **逐值相等**（281250 / 409671）。
即「金融→商科」这个降级**不发生在引擎里**，发生在引擎之前。

**平台机制（本次确权，务必记住）**：

- 平台跑技能时有**两个独立 LLM**：① 写回复的「内容模型」；② 取槽位的 **planner**
  （`execution_trace[].events` 的 `skill_plan` 事件，`planner: hailiang_runtime_llm`）。
- **planner 的 `required_references` / `selected_references` 恒为空**——
  它只拿到 `prompt_markdown`（= SKILL.md）+ 会话消息，**读不到 `references/` 下任何文件**。
- 它的 `parameters` 就是最终传给脚本的槽位；`reasoning` 里会写「根据 SKILL.md」。
- **planner 取「最近一轮」的值**——助手自己追问时列出的选项标签，会被用户回填，
  **回填值会覆盖用户最早说过的原话**。

**推论（对文案的三条硬要求）**：

1. 任何要求「模型必须照做」的规则，**只有写在 SKILL.md 正文里才可能被 planner 看到**；
   写在 `references/` 里对取槽位这一环**完全无效**。references 只服务写回复的内容模型。
2. **助手的追问话术会污染槽位**：一旦把问卷标签列出来，用户就可能改口，
   而系统采信的是改口后的值。**已给槽位不得再进问卷**（见 SKILL.md 输出红线「追问由脚本决定」）。
3. **专业名必须原样保留在回复正文里**（见 SKILL.md 输出红线「专业名原样保真」）。

**为什么这次金额没错却仍是严重缺陷**：金融恰属商科，所以侥幸对上。
换成下列输入就会被标签带偏而**静默算错钱**：

| 用户原话 | 正确大类 | 用户可能照标签选成 | 后果 |
|---|---|---|---|
| 建筑 | 工科 | 艺术 | **金额算错** |
| 临床 | 医学 | 理科 | **金额算错** |
| 传媒 | 文科 | 艺术 | **金额算错** |

**与 7.6 的区别（两者是不同链路，别混）**：

| | 7.6 专业大类归属回退 | 本节 |
|---|---|---|
| 病灶位置 | **引擎内** `_major_slot_value` 别名表认得少 | **引擎外** 平台取槽位 |
| 表现 | 槽位里有「金融」，但引擎认不出 → 裸透出 → `no_school_match` | 槽位里根本没有「金融」，已被改写成「商科」 |
| 修法 | 扩别名表 + 归属回退（**已修复，781/781**） | 提示词层：已给槽位不进问卷 + 专业名原样保留 |
| 能否靠改引擎解决 | 能 | **不能**——引擎收到时信息已丢 |

**验证口径**：

- 原样重放该会话的 8 条 `messages`，断言 planner 的 `parameters.major` 为「金融」，
  且**不出现**「你想读哪个专业方向」这类追问句。
- **反向用例（关键护栏）**：构造「用户说『建筑』」的会话，断言不退化、不被改写成「艺术」。
  这是真正会算错钱的情形，单测单国/单专业永远测不出来。

## 九、特殊地区与专业口径

参见 `assets/region_notes.json`。模型在结果里出现某国家/地区或某专业方向时，需按该文件的 `countries.<国家>.note`、`countries.<国家>.by_major.<专业>`、`zones.<专业>` 补一句当地口径，放在风险说明之前；没命中的不播报。关键提示：

- **医学**：北美 MD/DDS/DVM 为本科后专业学位；美国列出的是本科直入+医学连读项目本科阶段学费；德国公立医学院免学费；日本私立医大另缴一次性入学金。
- **艺术**：皇家艺术学院 RCA 仅研究生，未收录；日本艺术院校学费为“授业+设施”年额，入学金另缴；德国公立艺术院校免学费；法国公立为注册费制；意大利公立按 ISEE 档收费。
- **德国**：公立院校免学费，每学期缴学期费，本工具按学费 0 计。
- **法国**：公立为注册费制；私立学费自定。
- **瑞士**：学费按学期计，年额=每学期×2；外籍学生可能另收附加费。
- **韩国**：医学类专业普遍不招收国际学生。
- **中国香港**：采用非本地生学费标准。
