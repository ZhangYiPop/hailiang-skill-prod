# AGENT.md Skill 路由配置说明

本文面向在 AI 业务调试台维护专家（Agent）的业务人员。它说明如何在专家的 `AGENT.md` 顶部，维护专家已绑定 Skill 的结构化路由提示。

`AGENT.md` 同时包含两部分：顶部 YAML front matter 是简洁、可核验的路由提示；分隔线后的 Markdown 正文是专家的自然语言策略、例外规则、追问方式和直答边界。两部分会一起参与专家的最终判断。

## 推荐模板

```md
---
skill_routing:
  rules:
    - skill_id: study_question
      when:
        - 家长描述孩子头疼的学习行为，例如磨蹭、走神、粗心、不想学、沉迷手机或记不住。
        - 用户想了解学习困难的原因，并希望获得家庭可执行的改善办法。
      priority: 100
    - skill_id: interest_primary
      when:
        - 用户希望了解或培养孩子的兴趣特长。
---

# 专家策略

先结合用户的实际问题、已有事实和下列规则判断。……
```

`priority` 是可选项。不需要明确排序时，删除这一行即可。

## `when` 怎么写

`when` 必须是**字符串数组**。数组中的每一项是一条完整、自然语言的“适用条件”。推荐使用多行写法：

```yaml
when:
  - 家长描述孩子磨蹭、走神、粗心或沉迷手机，想了解原因与家庭可执行办法。
  - 用户已经明确孩子当前学习困难，希望获得诊断和改善建议。
```

同一数组中的多项是“任一项相关即可成为候选”的关系；它们不是必须同时成立的硬条件。专家仍会结合当前会话、`AGENT.md` 正文、其他授权 Skill 的规则，选择最合适的一个 Skill，或在无法区分时追问一个最小澄清问题。

### 单行写法

以下写法也是合法 YAML，语义与多行写法相同：

```yaml
when: [条件 A, 条件 B]
```

但长中文条件推荐使用多行写法，便于阅读、增删、审查和避免标点歧义。

注意：中文顿号 `、` 不是 YAML 数组分隔符。因此下面只有**一条**条件，不是两条：

```yaml
when: [条件 A、条件 B]
```

若需要两条条件，请写成 `when: [条件 A, 条件 B]`（英文逗号），或使用推荐的多行格式。

### 空条件

```yaml
when: []
```

表示暂不提供结构化适用条件。此时专家仍可通过 `AGENT.md` 正文和已绑定 Skill 的语义决定是否调用该 Skill。空条件适合刚创建、尚未梳理路由规则的专家，但建议在业务策略稳定后补充具体条件。

### 引号

条件含有 YAML 容易误解的字符时，建议加引号，尤其是冒号、`#`、开头的特殊符号等：

```yaml
when:
  - "用户提问中包含预算范围：每年 30 万以内。"
  - "用户咨询 #竞赛规划 或升学背景提升。"
```

## `priority` 怎么写

`priority` 是可选的整数排序提示。多个 Skill 同时匹配时，数值较大的规则优先：

```yaml
skill_routing:
  rules:
    - skill_id: study_cost_calculator
      when:
        - 用户询问留学预算、费用或计算。
      priority: 100
    - skill_id: study_consultation
      when:
        - 用户咨询一般留学问题。
      priority: 50
```

它不是绕过专家判断的硬编码开关，也不会允许调用未绑定的 Skill。若两个 Skill 无法可靠区分，专家仍应根据正文策略澄清，而不是机械地执行多个 Skill。

## 保存前的严格对应关系

只要 `AGENT.md` 中存在 front matter，`skill_routing.rules` 内的 `skill_id` 集合必须与当前专家实际锁定的 Skill 集合**完全一致**：

- 每个已绑定 Skill 必须恰好有一条规则；
- 不可重复写同一个 `skill_id`；
- 不可保留已经解绑的 `skill_id`；
- `skill_id` 必须填写且必须是字符串。

编辑页新增或更换已绑定 Skill 时，系统会自动为缺失的 ID 追加：

```yaml
- skill_id: 新的_skill_id
  when: []
```

它不会覆盖已有规则、`when`、`priority`、未知 YAML 字段或 `AGENT.md` 正文。移除 Skill 时，系统也不会自动删除规则，以避免误删人工策略；请在 YAML 中手动删除对应条目后再保存。

没有 front matter 的历史 `AGENT.md` 可以继续保存和运行，系统会仅依据正文及实际绑定的 Skill 进行路由。新建或维护中的专家建议逐步采用本规范，获得更可解释、可审核的路由提示。

## 常见错误

| 写法 | 问题 | 推荐写法 |
| --- | --- | --- |
| `when: 家长咨询学习困难` | `when` 不是数组。 | `when: [家长咨询学习困难]` |
| `when: [A、B]` | 只有一条条件，顿号不分隔数组项。 | `when: [A, B]` 或多行列表。 |
| 两条相同 `skill_id` | 保存会被拒绝。 | 每个绑定 Skill 仅保留一条规则。 |
| 解绑后保留规则 | 保存会被拒绝。 | 手动删除已解绑 Skill 的规则。 |
| 绑定了新 Skill 但未补充规则 | 保存会被拒绝。 | 使用编辑器自动补充的骨架，或手动添加对应 ID。 |
