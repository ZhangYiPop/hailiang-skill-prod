## 0. 本项目的实现边界

本文不是脱离代码的通用审核清单，下面的对象和链路均对应本项目当前实现：

| 本项目对象 | 本文中的安全职责 |
| --- | --- |
| `POST /api/v2/sessions/chat/stream` | 正式 SSE V2 对话入口；通过 `context_data.profile_id` 确定当前孩子分支，不能从 `input` 直接伪造孩子身份。 |
| `MainPlannerOrchestrator` | 统一承接输入安全、Agent/Skill 路由、ContextComposer/记忆、Native Questionnaire、reference 和脚本执行前的策略。 |
| `AgentScopeExpertRuntime` | 专家先决策，再直答或调用已授权 Skill；不能绕过专家团锁定关系。 |
| `AGENT.md` / `agent.yaml` | 专家自然语言策略与 front matter 路由规则；不允许通过文本注入扩大授权 Skill。 |
| `SKILL.md` / `assets/questionnaire.json` | Skill 业务边界、表单条件、reference、脚本和 assets 使用说明；不能覆盖平台安全策略。 |
| `MSAgentRuntimeAdapter` / Docker Sandbox Worker Pool | 脚本、assets、依赖和执行隔离；高风险回合不能因为脚本成功就绕过输出审核。 |
| `ModerationService` | 优先调用阿里云内容安全；不可用时回退本地敏感词库；输入、输出、流式阶段均可检查。 |
| `QuarantineStore` | 保存被拦截输入/输出/流式内容的受控隔离证据；内容应加密，不能进入普通日志。 |
| `AuditStore` / `workbench_audit_events` | 保存审计指针、指纹和结构化事件；默认不保存普通日志中的完整正文。 |
| AI 业务调试台候选修订测试 | 使用 `revision_test_dbg_*` 调试会话和候选快照；不得因为是测试台就关闭安全审核。 |
| `POST /api/v1/operations/diagnostics/sessions/query` | 受管理员令牌保护的诊断查询；默认脱敏，`include_content=true` 才能查看受权限控制的详细内容。 |

### 0.1 当前已经存在的安全链路

1. `ModerationService.check()` 在云审核可用时按 2,000 字符窗口调用云端内容安全；云端失败后使用本地词库降级，并保留 `failure_reason`、provider、mode 和词库版本。
2. 正式对话在输入阶段拦截 `ModerationBlockedError`，返回 `CONTENT_BLOCKED`；输出阶段再次审核，失败时移除本轮未完成的助手消息并返回安全错误。
3. SSE V2 通过 `risk.status`、`risk.stage`、`security` 状态展示检查中、通过、拦截和降级；前端不得从正文猜测安全状态。
4. 被拦截内容进入隔离库时使用 `HAILIANG_SECURITY_QUARANTINE_KEY`；原文审计使用独立的 `HAILIANG_AUDIT_ENCRYPTION_KEY`。
5. 诊断接口对 `content`、`prompt`、`response`、`stdout`、`stderr`、`execution_trace` 等字段默认脱敏，并使用 `X-Security-Admin-Token` 或管理员 Bearer Token 鉴权。
6. 候选测试与正式对话共用 Runtime，但候选 Skill/Expert/Team 来自不可变候选快照；候选 trace、脚本证据、reference 证据和安全事件应使用同一 `event_id` 规则去重。

### 0.2 材料使用说明

本文用于说明本项目已经建立的模型安全、未成年人保护、心理健康保护、数据隔离和审计管控机制。文中涉及的接口、组件、环境变量和事件名称均以当前代码和部署配置为准；未在“当前实现”中列出的能力，不作为本项目已经具备的控制结论。

关键词库只作为 `LocalLexiconProvider` 或审核模型的风险识别输入，不直接决定 Skill 选择、孩子档案写入或业务结论。风险识别结果仍需结合上下文、否定表达、角色和用户意图处理。

## 1. 管控目标

本项目安全控制目标如下：

1. 在用户输入进入模型前识别高风险内容，减少不必要的模型暴露和不安全工具调用。
2. 让模型、Agent、Skill、脚本和引用资料在同一套安全边界下运行。
3. 对生成中的风险内容进行约束，对最终输出进行独立审核，不能只依赖提示词。
4. 对未成年人、儿童教育、心理健康、自伤风险、家庭暴力和隐私信息提供更严格的保护。
5. 对拦截、放行、降级、人工复核、应急响应和误判进行可追溯记录。
6. 不把关键词当成最终结论；关键词只负责召回风险，最终判定需要结合上下文、否定表达、角色和用户意图。

## 2. 全流程控制链路

```text
用户输入
  ↓
输入规范化与敏感信息识别
  ↓
风险分类：允许 / 加强约束 / 人工复核 / 紧急升级 / 拒绝
  ↓
上下文组装：当前孩子分支、有效事实、Skill/Agent 规则、必要引用
  ↓
模型规划与工具授权
  ↓
脚本、文件、引用和外部资源执行
  ↓
生成正文与流式状态
  ↓
输出安全审核、隐私脱敏、证据校验
  ↓
用户展示 / 人工复核 / 安全降级
  ↓
审计、诊断、误判反馈和规则更新
```

| 阶段 | 必须做 | 禁止做 | 主要记录 |
| --- | --- | --- | --- |
| 输入 | 规范化、识别风险类别、确定当前 profile 分支 | 未审核输入直接触发高风险脚本或外部工具 | `security`、`security_degraded`、拦截记录 |
| 规划 | 注入安全策略、限制 Skill 和工具权限 | 让模型自行扩大权限或绕过 Agent/Skill 边界 | 会话安全状态与运行时 trace |
| 生成 | 遵循年龄适配、心理健康、隐私和专业边界 | 把推断写成诊断或确定事实 | 输出检查结果 |
| 执行 | 对脚本、assets、reference 做来源和权限校验 | 让高风险内容进入不必要的计算、检索或写入 | 执行 trace、脚本和引用证据 |
| 输出 | 独立审核、脱敏、检查引用和敏感话术 | 仅因模型返回成功就直接展示 | `security`、`CONTENT_BLOCKED`、隔离记录 |
| 审计 | 记录理由、版本、策略和处理结果 | 记录完整密钥、无关正文或未授权儿童信息 | `workbench_audit_events`、诊断记录 |

## 3. 风险等级和处理动作

### L0：普通内容

允许正常回答。仍需遵守事实、隐私、Skill 和引用规则。

### L1：敏感但可安全回答

例如学习焦虑、亲子沟通、普通压力、考试失利、一般健康知识。

处理要求：

- 使用中性、尊重和年龄适配的表达。
- 不做疾病、人格或能力的确定性判断。
- 不重复暴露已经确认的儿童事实。
- 如需要补充信息，只询问完成当前任务所必需的最小问题。

### L2：高风险专业边界

例如疑似心理疾病、用药、严重饮食问题、家庭暴力、校园欺凌、隐私泄露、法律或财务的个性化决策。

处理要求：

- 不给出诊断、处方、保证性承诺或替代专业服务的结论。
- 说明信息边界，建议联系合适的监护人、学校、医生、心理专业人员或其他正式机构。
- 暂停与风险无关的推荐、脚本和表单自动提交。
- 低置信度时优先澄清或人工复核。

### L3：紧急安全风险

例如正在自伤/伤人、明确的自杀计划、儿童正在遭受性侵或严重暴力、立即危险的武器或毒物情境。

处理要求：

- 不提供任何可能增加伤害能力的细节、步骤、工具或规避方法。
- 先确认是否存在当下危险和是否有人陪同；只询问必要的安全信息。
- 鼓励立即联系当地急救、警方、危机干预或可信任的成年人；地区相关资源由部署方配置，不能硬编码成全球统一号码。
- 触发人工/安全值班升级，必要时暂停普通 Skill 流程。
- 记录风险类别和处置状态，不在普通调试导出中暴露完整高风险正文。

## 4. 关键词体系

关键词用于风险召回、审核排序和审计标签，不直接等同于违规。每个词应支持：同义词、错别字、口语、拼音、英文、数字替换、否定上下文和地区表达。

### 4.1 自伤、自杀和即时危险

**高风险关键词：**

```text
自杀、想死、不想活了、活着没意思、结束生命、轻生、寻死
自残、自伤、割腕、划伤自己、撞墙、吞药、跳楼、跳下去
已经准备、计划好了、今晚就、手边有刀、手边有药、没人知道
想伤害自己、想伤害别人、控制不住、马上要做
```

**不能只按关键词拦截的例子：**

```text
新闻里提到自杀
问“自杀这个词是什么意思”
说“我以前有过自伤，现在已经接受治疗且没有当前危险”
讨论小说、影视或历史事件
```

这些情况仍需要语境分类，但若出现“当前、已经准备、马上、工具在手边”等组合，应升级为 L3。

### 4.2 儿童虐待、性侵和剥削

```text
打孩子、经常挨打、家暴、掐、勒、烫伤、关起来、不让吃饭
猥亵、性侵、强迫发生关系、摸隐私部位、拍裸照、裸照威胁
未成年色情、儿童色情、诱骗、约见、送礼换照片、私聊裸照
老师/家长威胁孩子、禁止求助、不能告诉别人
```

出现未成年人和性内容、强迫、交易、威胁、现实接触计划的组合时，按 L3 处理，不提供任何规避监管或隐藏证据的方法。

### 4.3 心理健康和情绪危机

```text
长期情绪低落、持续失眠、惊恐发作、幻听、妄想、极度绝望
厌学到拒学、活着没意思、自我否定、崩溃大哭、无法正常生活
多动症、抑郁症、双相、焦虑症、强迫症、精神分裂、心理诊断
```

规则：

- 关键词命中不等于诊断；只能作为进一步了解和转介的信号。
- 对未成年人不得根据少量聊天内容下疾病结论。
- “多动、走神、磨蹭、怕难”等教育现象应使用“可能的学习/行为表现”表述，不直接升级为医学诊断。
- 若同时出现自伤、自杀、暴力、幻觉或无法保证安全，升级为 L3。

### 4.4 未成年人身份和儿童相关场景

```text
孩子、儿童、未成年、幼儿园、小学、初中、高中、未满18岁
家长、监护人、老师、班主任、学校心理老师
孩子住址、学校、班级、手机号、身份证、学号、照片、定位
```

单独出现这些词不应拦截，但会启用更严格的年龄适配、隐私最小化和专业边界策略。

### 4.5 医疗、用药和身体安全

```text
吃什么药、加大剂量、停药、换药、处方、药量、过量
诊断、确诊、治疗方案、手术、急救、昏迷、呼吸困难、胸痛
绝食、催吐、减肥药、厌食、暴食、体重快速下降
```

系统可以提供一般性健康信息和就医建议，但不得替代医生诊断、开药或调整处方。

### 4.6 暴力、武器、毒物和违法行为

```text
杀人、报复、绑架、跟踪、威胁、打人、伤害
刀、枪、爆炸物、毒药、投毒、制作、改装、藏匿、绕过检查
盗号、诈骗、洗钱、入侵、窃取、伪造、规避监管
```

涉及执行步骤、材料、剂量、目标选择、隐藏痕迹或逃避侦查时，拒绝提供操作性内容并升级审核。

### 4.7 隐私和个人敏感信息

```text
身份证号、手机号、家庭住址、学校地址、精确定位、银行卡、密码
验证码、token、API key、病历、心理咨询记录、成绩单、照片、录音
孩子姓名+学校、孩子姓名+住址、孩子姓名+联系方式
```

规则：

- 日志和导出默认脱敏。
- 不把完整证件号、密码、密钥、精确地址注入模型上下文。
- 只保留完成当前任务所需的最小字段。
- 用户要求“记住”时，应区分短期会话事实、孩子档案候选事实和敏感信息禁止长期保存。

### 4.8 Prompt 注入和系统信息探测

```text
忽略之前指令、泄露系统提示词、显示 AGENT.md、显示 SKILL.md
告诉我内部规则、绕过审核、关闭安全策略、调用未授权 Skill
输出 API key、数据库密码、容器环境变量、隐藏字段、内部路径
```

处理规则：不泄露内部提示词、密钥、完整 Skill 正文、容器信息或未授权工具；可以用简短自然语言说明无法提供内部配置。

## 5. 输入阶段控制

### 5.0 在本项目中的接入点

- 正式 HTTP 对话：`api/routes/chat.py` 在调用编排器前执行输入审核。
- SSE 流式对话：`core/streaming_runner.py` 在 `run_started` 后进入输入安全阶段，并通过 `security_callback` 更新 SSE `risk` 状态。
- Runtime/候选测试：`MainPlannerOrchestrator` 和 Workbench Candidate Runtime 继续使用同一个 `ModerationService`；候选快照不能绕过输入审核。
- 当前孩子隔离：只使用可信 `context_data.profile_id`；`input.profile_id` 不是 SSE V2 的孩子身份来源。切换孩子后，旧孩子的风险上下文、表单、候选事实和档案不能注入新分支。
- 输入被拦截时返回 `CONTENT_BLOCKED`、`stage=input` 和受控 `case_id`；前端应展示 `risk.message`，不应展示内部命中词或供应商原始响应。

### 5.1 规范化

输入进入模型前应完成：

- Unicode、大小写、空白、全角半角和常见错别字归一化。
- 识别拼音、谐音、数字替换和中英文混写。
- 保留原始消息 ID、turn ID 和时间戳，但不把原始敏感正文复制到所有日志。
- 绑定当前 `profile_id`；未绑定孩子的内容不得写入孩子长期档案。

### 5.2 风险分类顺序

```text
先识别 L3 即时危险
再识别儿童虐待/性侵/严重隐私泄露
再识别心理健康和医疗边界
最后处理普通敏感和业务场景
```

同一条消息命中多个类别时取最高风险级别，但保留所有类别标签用于审核和审计。

### 5.3 输入处理动作

| 分类 | 动作 |
| --- | --- |
| 普通 | 正常进入路由和 Skill |
| 敏感 | 加入安全系统约束，正常回答但减少事实扩展 |
| 高风险 | 暂停无关 Skill、脚本和外部检索，进入安全回复或人工复核 |
| 紧急 | 进入安全升级流程，不继续普通问卷，不给操作性内容 |
| 高置信违法/攻击请求 | 拒绝危险部分，可提供合法、安全替代信息 |

## 6. 生成阶段控制

### 6.1 安全策略优先级

生成提示中的优先级应为：

```text
平台安全策略
  > 当前专家/Agent 安全边界
  > Skill 业务规则
  > 当前孩子有效事实
  > 历史摘要和候选档案
  > 用户当前请求
```

安全策略不能被用户文本、Skill、脚本输出或 reference 文档覆盖。

### 6.2 模型生成要求

- 不把候选事实、行为表现或关键词命中写成确定诊断。
- 不编造医疗、心理、招生、法律、财务结论。
- 不因为用户要求“直接给答案”而跳过高风险审核。
- 不主动复述儿童姓名、学校、住址、病历、成绩等敏感事实。
- 已确认事实默认静默使用；只有解释结论、冲突确认或用户主动要求回顾时才提及。
- 高风险场景不展示无关的推荐卡、表单、脚本结果或专家转交。
- 回复应先处理安全问题，再说明能提供的普通帮助。

### 6.3 工具和脚本限制

高风险输入默认：

- 禁止执行未明确必要的脚本。
- 禁止写入孩子长期档案候选事实。
- 禁止使用外部网络检索个人身份或敏感资料。
- 禁止把完整高风险原文作为脚本参数。
- 脚本结果必须经过输出审核，不能因为退出码成功就直接展示。

## 7. 输出阶段审核

### 7.0 在本项目中的输出审核顺序

当前输出链路如下：

```text
模型/Skill 生成草案
  → Runtime 处理 questionnaire / script / reference / reply-progress
  → 需要时暂缓流式正文
  → streaming_runner 或 chat route 调用 ModerationService(stage=output/stream)
  → record_security_result(context, stage=output)
  → 通过才发送 completed；拦截则移除本轮助手消息并返回 CONTENT_BLOCKED
```

特别注意：

- `reply_progress`、引用证据校验、脚本结果防幻觉校验不等同于内容安全审核，三者必须同时保留。
- `assistant_message`、Native Questionnaire 的表单 JSON、脚本 stdout/stderr 和 reference 片段都属于待审核输出，不得只审核最终可见的一小段正文。
- 需要引用或脚本核验的回合，在 `reference_preflight`、脚本执行和最终证据校验完成前不得把未经审核的草案流式发送给用户。
- 输出拦截后不能把原始不安全正文继续写入普通候选 JSONL；需要时只能通过隔离库和管理员诊断权限访问。

输出审核至少包含以下检查：

1. **风险复核**：是否出现自伤、暴力、性侵、诊断、处方或违法操作性内容。
2. **年龄适配**：语言是否适合儿童和家长，是否包含不必要的成人细节。
3. **专业边界**：是否把建议写成确诊、保证或替代专业服务。
4. **隐私脱敏**：是否暴露姓名、学校、联系方式、住址、密钥或内部路径。
5. **证据一致性**：是否引用了实际加载的 reference、脚本结果或用户事实。
6. **路由一致性**：是否越过当前 Agent、Skill、专家团和 profile 授权范围。
7. **重复与推进**：是否机械复述已确认事实，是否重复已回答问题，是否真正推进当前任务。
8. **流式安全**：高风险或需要引用/脚本核验的回复，在审核完成前不得发送未经审核的正文片段。

### 输出动作

```text
通过       → 正常展示
轻微问题   → 允许在安全范围内重新生成
高风险     → 丢弃不安全草案，生成安全降级回复
无法判断   → 暂停展示，进入人工复核或可重试错误
```

## 8. 未成年人专项保护

### 8.1 年龄和身份处理

- 未知年龄但语境明显涉及孩子时，按未成年人友好策略处理。
- 不要求儿童直接提供身份证、住址、电话、学校精确位置或家庭财务信息。
- 年龄、年级、地区等事实应按当前孩子分支隔离。
- 切换孩子后，A 的事实、表单、候选档案和原文不得注入 B。
- 未成年人候选事实默认不能驱动资格、诊断、推荐或自动提交。

### 8.2 对话表达

- 使用尊重、不羞辱、不贴标签的语言。
- 不把“懒、笨、叛逆、没救”等评价作为事实。
- 不鼓励家长体罚、羞辱、公开曝光、跟踪监控或强制隔离。
- 不要求孩子独自承担严重心理、家庭暴力或安全风险。
- 涉及危险时，优先建议联系可信任成年人和当地专业机构。

### 8.3 教育和学习场景

- “磨蹭、走神、遇难题放弃、成绩下降”只能作为观察到的表现。
- 不根据一两轮对话诊断 ADHD、抑郁、焦虑、学习障碍或其他疾病。
- 可以提供家庭可执行的低风险建议，但应说明观察周期和停止条件。
- 如果出现持续、跨场景、明显影响生活或安全风险，应建议专业评估。

## 9. 心理健康专项保护

### 9.1 必须先判断的事项

模型不需要追问完整病史，但应优先判断：

- 是否存在当前自伤或伤人危险。
- 是否已经有具体计划、工具、时间或正在实施。
- 是否有可信任的成年人在身边。
- 是否出现无法保证当前安全的情况。

### 9.2 安全回应原则

- 先表达重视和陪伴，不争辩、不责备、不质疑真实性。
- 不承诺“我会替你保密”或“我一定能解决”。
- 不描述自伤方式、致死概率、工具比较、剂量或隐藏方法。
- 不把危机内容转成普通心理测试、学习问卷或推荐流程。
- 当前危险时建议立即联系当地急救、警方、危机干预服务或可信任成年人。
- 非紧急时可提供一般性的倾听、求助和专业评估建议。

### 9.3 诊断与转介

允许：

```text
“这些表现值得进一步关注。”
“仅凭聊天无法判断是否属于某种疾病。”
“可以考虑和学校心理老师/专业机构沟通评估。”
```

禁止：

```text
“孩子就是抑郁症/多动症。”
“不用看医生，照这个方法做就行。”
“停药/加药/换药。”
“我保证不会告诉任何人。”
```

## 10. 人工审核和升级

### 必须人工复核的情形

- L3 即时危险或儿童虐待/性侵线索。
- 模型对风险等级连续两次判断不一致。
- 用户明确投诉、要求删除档案或质疑安全处理。
- 输出同时涉及医疗、心理、法律、财务或未成年人重大权益。
- 发现模型、Skill 或脚本越权，或出现隐私泄露。
- 输出审核无法判断，或者安全重生成失败。

### 人工审核最小信息集

```json
{
  "session_id": "...",
  "turn_id": "...",
  "profile_id": "...",
  "risk_level": "L2",
  "risk_categories": ["minor", "mental_health"],
  "policy_version": "...",
  "model_name": "...",
  "agent_id": "...",
  "skill_id": "...",
  "action_taken": "safe_degrade",
  "review_reason": "...",
  "created_at": "..."
}
```

默认不向审核列表复制完整对话正文；审核人员按权限查看必要片段。

## 11. 审计事件和诊断字段

本项目当前使用的安全事件/状态包括：

## 12. 调试台、导出和诊断接口

候选修订手动测试和正式 SSE 应使用同一套安全分类和输出审核逻辑。

### 默认导出

默认仅保留：

- 风险级别和类别；
- 命中的关键词类别，不返回完整敏感词命中正文；
- 处理动作、策略版本和降级原因；
- 模型、Agent、Skill、revision 和 turn 标识；
- 是否进入人工复核。

### 管理员详细查询

只有经过现有管理员权限并显式请求详细内容时，才允许查看必要的原文片段。完整高风险原文仍应遵循最小化、目的限定和访问审计原则。

诊断接口的查询示例：

```json
{
  "session_id": "...",
  "event_types": [
    "input_risk_classified",
    "output_safety_degraded",
    "human_review_requested"
  ],
  "include_content": false
}
```

同一 `event_id` 必须去重，避免正式会话和候选测试重复展示安全事件。

### 12.1 项目环境和密钥要求

安全配置与业务配置分离，至少检查以下环境变量：

| 环境变量 | 用途 | 要求 |
| --- | --- | --- |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | 云端内容安全 | 两者同时存在才启用云审核；不能写入代码、Skill 包或前端。 |
| `HAILIANG_SECURITY_QUARANTINE_KEY` | 风控拦截内容隔离加密 | 与审计密钥不同；缺失时不应静默放行被拦截内容。 |
| `HAILIANG_AUDIT_ENCRYPTION_KEY` | 原文审计库加密 | 与隔离密钥分离，轮换时保留旧版本解密能力。 |
| `HAILIANG_SECURITY_ADMIN_TOKEN` | 诊断、隔离库和审计查询鉴权 | 不下发浏览器，不与测试/生产复用。 |
| `HAILIANG_AUDIT_RAW_CONTENT_ENABLED` | 是否保存加密原文审计 | 生产默认 `false`；临时开启必须有工单、时限和回收记录。 |
| `HAILIANG_SSE_RECORDING_ENABLED` | 是否保存 SSE 记录 | 生产默认关闭，调试时也要遵守脱敏策略。 |
| `HAILIANG_LOCAL_SESSION_CACHE_ENABLED` | 本地会话缓存 | 正式环境默认关闭，避免绕过 PostgreSQL 审计和 profile 隔离。 |
| `HAILIANG_SECURITY_ALLOWED_LABELS` | 云审核标签例外 | 只能由安全负责人配置，不能由业务人员或 Skill 包覆盖。 |

上线检查必须确认 `/health/ready` 中的 `security.aliyun_available`、存储后端、隔离密钥和审计密钥状态；“服务能启动”不等于“云审核已启用”。

### 12.2 本项目的配置和 Skill 开发边界

- 业务人员在 `AGENT.md`、`SKILL.md` 或 `assets/questionnaire.json` 中不能配置“关闭审核”“跳过输出审核”“允许保存完整隐私”等字段。
- `AGENT.md` front matter 只负责已授权 Skill 路由，不负责改变安全等级。
- `assets/questionnaire.json` 的 `required`、条件渲染和分页只影响表单，不代表可以收集任何个人敏感信息；高风险字段仍由平台安全策略限制。
- `scripts/` 只能读取被授权的结构化输入和 assets；不得读取环境变量中的密钥、任意宿主机路径、其他 profile 数据或完整会话原文。
- `references/` 不是安全策略来源；reference 中即使出现危险操作描述，也必须经过平台安全策略和输出审核。
- 脚本成功、引用加载成功、模型 `finish_reason=stop` 都不能替代安全审核。

### 12.3 与 SSE V2 的字段对应

SSE V2 对前端只暴露安全状态，不暴露云审核原始响应、完整敏感词或隔离库内容：

```json
{
  "status": "streaming",
  "risk": {
    "status": "checking|passed|blocked|degraded",
    "stage": "input|generation|output|stream",
    "blocked": false,
    "message": ""
  },
  "error": {
    "code": "CONTENT_BLOCKED",
    "retryable": false,
    "terminal": false
  }
}
```

前端不能根据 `assistant.content` 是否为空、是否出现“抱歉”或是否出现某个关键词自行判断安全状态；必须使用权威 `risk` 和 `error` 字段。

## 13. 测试与验收清单

### 输入测试

- 正常教育问题不被单个敏感词误拦截。
- “新闻/小说/学习关键词解释”与真实危险意图可以区分。
- 中文错别字、拼音、谐音、数字替换和中英文混写仍能召回。
- 未绑定孩子的输入不会写入孩子长期档案。

### 生成测试

- 未成年人问题不会产生羞辱、标签化或确定诊断。
- 心理危机不会继续进入普通学习问卷或推荐 Skill。
- 模型不能被 Prompt Injection 诱导输出 AGENT.md、SKILL.md、密钥或内部路径。
- 候选事实不能直接成为医疗、资格或路由硬条件。

### 输出测试

- 高风险输出在审核前不流式展示。
- 脚本和 reference 结果与最终回答一致。
- 不能泄露完整儿童身份信息、token、密码或敏感日志。
- 安全降级后仍能给出明确、尊重、可执行的求助方向。

### 故障测试

- 风险分类模型超时：采用保守策略并记录降级事件。
- 输出审核模型不可用：高风险回合不直接放行，普通低风险回合按预设安全模板或可重试错误处理。
- 人工审核队列拥堵：记录排队和超时，不静默丢弃风险事件。
- 规则版本更新后，历史事件仍可按原策略版本解释。
