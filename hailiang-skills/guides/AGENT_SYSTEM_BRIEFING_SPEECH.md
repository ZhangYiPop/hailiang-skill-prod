# Agent 系统向上汇报讲稿

## 一句话定位

这套系统不是一个只会聊天的大模型外壳，而是一套面向生涯规划场景的智能服务系统。它的核心价值，不是把问题答完，而是把用户从“我有点迷茫”一步步带到“我下一步该做什么”，并且在这个过程中持续沉淀信息、判断方向、按需调用合适的专项能力。

## 口头讲稿

如果让我用一句话介绍这套 Agent 系统，我会说，它是一个面向生涯规划的“统一调度 + 专项能力协同”的智能系统。

它最上层对外看到的是一个统一的对话入口，但在内部，它不是把所有问题都丢给同一个模型去回答，而是先做判断，再做分发，再做结果整合。也就是说，用户不需要先自己理解“我这个问题到底该问谁”，系统会先理解当前诉求是在泛咨询、选科、多元路径、兴趣探索、提分还是模拟升学，然后把问题导向最合适的专项能力模块。

从架构上看，我们现在已经形成了一个比较完整的闭环。前面是统一接入层，负责承接前端和会话请求；中间是一层统一调度层，负责理解当前上下文、管理会话状态、判断是否需要切换场景；再往下是规划中枢和多个专项能力模块，比如选科参谋、兴趣探索、多元路径规划、模拟升学、提分规划等。最后，系统会把本轮结论、用户画像、关键事实和下一步建议再统一写回状态层，并通过流式协议实时返回给前端。

我觉得这套系统真正体现“智能”的地方，主要有四点。

第一，它不是一刀切地切场景。用户一上来哪怕表达得很模糊，系统也不会强行把他推进某个固定流程，而是先接住问题，判断当前诉求是否已经足够明确。明确的，就直接进入对应能力；不明确的，就先用主顾问模式做一层判断和收口。

第二，它不是固定问卷，而是边问边给。也就是说，它不会为了“收集完整信息”而机械追问，而是只补那些真的会影响下一步判断的信息。用户已经说过的内容会尽量复用，避免重复提问。这样体验上更像一个有经验的规划顾问，而不是一个流程机器人。

第三，它不是把所有知识一次性塞给模型，而是按需调用。只有在当前问题确实需要时，系统才会去加载相关知识、规则、结构化资产或者专项工具。这样做的好处，一方面是让回答更聚焦，另一方面也能降低模型泛化过度、答非所问或者信息污染的概率。

第四，它不是只靠模型主观生成答案，而是让结构化能力参与判断。比如在选科这种高风险场景下，系统不会只凭语言模型“感觉”来给建议，而是会结合规则、结构化数据和可复核的查询能力再输出结果。这样更适合做真正有业务责任的规划建议。

如果说“按需调用”怎么理解，我会举几个很具体的例子。

比如用户只是说“孩子未来怎么规划，我现在有点没头绪”，系统不会立刻给一个很重的结论，而是先进入顾问式判断，结合年级、成绩、兴趣、特长这些信息，先判断当前最值得切入的是选科、兴趣方向，还是多元路径。  
如果用户的问题已经很明确，比如“高一怎么选科”“物化生和物化地怎么选”，那系统就可以直接调到选科能力模块。  
如果用户问的是“除了普通高考还有没有别的升学路径”，系统就会把它识别为多元路径规划类问题。  
如果用户问“这个分数大概能上什么学校”，那就会导向模拟升学能力。  

所以这套系统不是“只有一个大脑”，而更像是有一个总调度，再去协调多个专项顾问能力一起完成服务。

那它怎么体现“生涯规划”能力，而不只是解答单点问题？我觉得关键在三个地方。

第一，它会持续复用上下文。孩子的学段、成绩水平、兴趣特长、选科倾向、历史对话结论，系统都会尽量沉淀下来，后面再做判断时不需要每次从零开始。

第二，它关注的不是“当前问题有没有答出来”，而是“下一步该往哪里走”。所以它不仅会给结论，还会给推荐方向、下一步动作，帮助用户从模糊问题进入更具体的规划场景。

第三，它支持从泛咨询走向专项决策。很多家长一开始并不会准确表达自己到底需要的是选科建议、升学路径判断，还是兴趣方向收敛。系统现在已经可以先做一层顾问式归纳，再把问题平滑带入最合适的专项模块，这一点其实非常符合真实生涯规划服务的工作方式。

如果从目前已经实现的效果来看，我觉得可以概括成三点。

第一，用户不需要自己理解复杂的服务边界，系统能够帮他找到当前最合适的入口。  
第二，规划过程是连续的，不是每换一个话题就重新开始。  
第三，前端拿到的不只是文本回复，还有状态、建议和下一步动作，所以整体交互会更完整，也更接近真正可落地的智能规划服务。

当然，这套系统也不是已经完全做完了。下一阶段我认为最值得继续投入的有三件事。

第一，是把调度规则进一步统一。这样后续新增能力模块时，接入成本会更低，整体行为也会更稳定。  
第二，是把规划主链路继续收敛。这样既能降低维护复杂度，也能让后续功能迭代更快。  
第三，是把数据沉淀和效果评估闭环做得更完整。只有持续看得到用户进入了哪些场景、卡在哪些环节、哪些建议真的有效，我们才能把“规划能力”做得越来越成熟。

如果最后做一个总结，我会说，这套系统的价值，不在于把一个问题答得多漂亮，而在于它已经具备了面向生涯规划场景的基本系统能力：能理解用户意图、能按需调用专项能力、能沉淀规划过程、也能把下一步路径交付给用户。它不是一个单点模型能力的展示，而是在往“真正可持续服务用户的智能规划系统”这个方向走。

## 汇报时可强调的关键词

- 统一调度
- 专项能力协同
- 边问边给
- 按需调用
- 结构化核对
- 状态沉淀
- 连续规划
- 下一步建议

## 不建议在汇报中展开的内容

- 底层运行时品牌或框架名词
- 内部路由字段名
- 具体脚本、文件名、目录结构
- 过细的桥接实现方式
- 暂无证据支撑的量化指标
