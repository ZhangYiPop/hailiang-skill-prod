# Harness 上下文策略 v2：实现与发布依据

日期：2026-10-18。基线：`e47424d`（合并后的 `codex/subagent-development-zhangyi`）。实现位于独立工作树 `harness-context-v2`，不覆盖原工作树的未提交改动。

## 决策与发布状态

采用结构化任务书、节点独立消息、按字段投影事实、结构化结果与按引用读取证据。复用已有 run JSON、事实表、工具记录和检查点；不引入向量数据库、共享自由写入记忆池或数据库迁移。本次没有接通 `orchestrator_v2`。

**默认仍为 v1。** `HAILIANG_CONTEXT_POLICY=v2` 只影响新建 run；run 创建时固定 `context_policy_version`。缺少版本的旧 run 按 v1 继续，修改开关不会改变已有执行。回退时撤销环境变量或设为 `v1`，既有 v2 run 仍须由支持 v2 的版本完成。

单次输入上限 64,000、整轮累计输入 300,000、主 agent 预留 32,000 沿用原配置。本地测试的自定义 policy 可以覆盖这些值，不代表生产默认调整。

累计输入是多次请求输入之和，不是单次上下文窗口。新增 `HAILIANG_HARNESS_MAX_RUN_INPUT_TOKENS=0` 可关闭新 run 的累计输入硬限制，仍记录用量，保留单次上下文及模型／工具次数限制。该值随 policy 快照固定，旧 run 不受后续环境变量修改影响。定向回放仍保持默认 300,000，避免通过放大预算掩盖重复调用。

## 协议与上下文边界

`harness/context_policy.py` 提供可独立复用的 `TaskBrief`、`TaskResult`、事实投影、证据授权与 composer。新协议使用版本 `v2`，`delegate_tasks`／`execute_skill` 的原必填参数不变，新增可选 `brief`。服务端补入原始请求、对象身份、父任务目标与继承的约束；权限始终由配置快照和调用主体决定。未提供任务书的旧调用无需额外模型补全。

System 包含平台、角色、必要 Skill 规则；动态任务书、事实、问答状态、摘要和目录放入明确标记为资料的上下文消息。工具保留原生 assistant/tool 配对及原 `tool_call_id`。子节点不复制父节点完整历史或其他专家轨迹。

事实来源包括 Skill 字段声明、任务书字段、显式补读、已使用版本和请求直接匹配字段。未投影字段提供有界索引；索引不是字段值，未加载不等于未知。`read_facts(keys?, known_versions?)` 定向或增量返回，随后每次模型输入仍包含已使用的当前值。被更正的旧 read_facts 消息投影为当前事实引用，原始工具记录不改写。

追问按存储身份、字段、可选 subject／applicable_time 匹配；复用值须通过当前表单校验。相同待答请求绑定多个任务，保持单张可答卡片与专家归属；跳过可复用，澄清需理由。新答案绑定所有消费者的事实版本。问答工具内容已完整出现在当前事实时改用引用，避免答案重复注入。

专家和 Skill 可调用 `submit_result`，主 agent 无此工具。工具依赖未解决时拒绝提交；服务端决定执行终态。结构化结果保留结论、依据、限制、未解决项、证据和事实版本。约 1,200 token 是软目标：长结论原文保存为证据，限制和关键字段不机械截断；每个专家保持独立结果包。旧文本输出仍可读取。

`read_evidence` 只允许本节点证据或显式授权引用，范围限定当前 run；偏移与长度由工具 schema 校验（单片最多 8,000 字符）。结果返回来源版本和哈希。祖先必须显式传入引用；依赖任务和子任务结果向消费者授予对应结果与引用。事实版本变化后旧证据标记失效，不能重新作为有效依据读取。证据不提供任意任务轨迹读取入口。

## 整理、预算与诊断

达到单次预算 70% 时，先用持久化引用替换较早的已完成长工具资料，再按完整交互分块摘要，目标低于 50%。摘要调用只带精简规则、此前摘要和待整理块，不重复整个角色与事实输入。未解决工具交互、用户原话、问答和事实写入交互受保护；摘要失败保留检查点和错误，不生成用户追问。保护内容本身超限时返回可定位错误。

事实、问答、规则、任务书、摘要、历史、工具证据和工具定义分别计量；分项是估算值，消息封装会有额外开销。供应商实际输入、输出、缓存命中／未命中、耗时分开记录；没有 usage 则明确保留估算。预算在数据库事务中预留，成功取得 usage 后幂等校正；缓存命中不抵扣逻辑输入预算。

调试台新增按节点／调用展开的诊断视图，原始 trace 保留最终模型输入、授权工具、原始输出和压缩记录。公开启动、回答、取消 API 不变，普通用户工作气泡不显示内部提示词。

## 验证与已知限制

首轮回放发现模型将资产路径误填为证据 ID。后续修正让普通工具结果显式返回 `evidence_id` 与 `data`，说明只接受 `ev_` ID，已有正文无需为取得引用重复读取；服务端授权校验不放宽。同时恢复主 agent 原有专业任务优先分派职责，明确分轮业务追问应通过专家输入工具执行。后续定向回放独立存档，不覆盖首轮失败依据。

回归测试、PostgreSQL 实测和真实模型对照见同目录验收报告。回放使用虚构输入与冻结配置，保存模型、配置指纹、实现指纹、每次输出和工具链；不得把自动统计当作事实正确性的验收。

- 字段相关性目前是显式声明与确定性匹配，不是语义检索；声明缺失时可能需要额外补读。
- 证据保存在现有 run JSON，长运行的存储体积仍会增长；此次优化模型输入而非存储体积。
- 超长限制／关键字段受保护，无法保证每份内部结果都低于软目标。
- 明确用户更正仍需事实工具落库，摘要不能成为事实权威；真实模型是否及时更新必须逐例复查。
- 模型选择调用次数可能变化；缩短单次输入不等于整轮成本必然下降。
- 默认启用门槛：权限／协议测试通过，真实回放无新增关键事实错误或约束丢失，完成率和重复追问不劣于 v1，总累计输入中位数下降。任一未满足，保持 v1 默认。

## 复现

后端在 `hailiang-skills` 目录运行：

```sh
PYTHONPATH=src python -m pytest -q tests/test_harness_context_v2.py tests/test_harness.py
PYTHONPATH=src python scripts/replay_context_policy.py --env-file /path/to/env.local.sh --output /tmp/context-replay.json --repeats 3 --timeout 150
```

真实回放会调用当前配置的供应商并产生用量。脚本只按数据解析凭证文件，不执行其中 shell；报告不保存凭证。PostgreSQL 测试仅使用专用测试库，设置 `HAILIANG_HARNESS_TEST_DATABASE_URL`；不要指向业务数据库。前端运行 `npm run check`。
