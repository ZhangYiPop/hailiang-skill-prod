## 四、系统架构与功能链路

系统采用“前端聊天界面 + FastAPI 后端 + Skill Runtime + 第三方大模型 API + 本地结构化资产”的架构。

```text
用户/家长
  -> 前端 React 聊天界面
  -> FastAPI /api/v1/sessions、/messages、/messages/stream
  -> MainPlannerOrchestrator
  -> Intent Router / Skill Runtime
  -> 本地 facts、references、assets/generated 检索与规则筛选
  -> 第三方大模型 API 生成回复或工具调用规划
  -> 输出清洗、message blocks、route suggestions、日志记录
  -> 返回前端展示
```

主要接口：

| 接口 | 说明 |
| --- | --- |
| `POST /api/v1/sessions` | 创建会话，绑定 `user_id` 和可选 `profile_id` |
| `POST /api/v1/sessions/{session_id}/messages` | 同步发送消息并返回 assistant 回复 |
| `POST /api/v1/sessions/{session_id}/messages/stream` | SSE 流式发送消息 |
| `GET /api/v1/sessions/{session_id}` | 查询会话摘要 |
| `GET /api/v1/sessions/{session_id}/context` | 查询会话上下文 |
| `GET /api/v1/sessions/{session_id}/events` | 查询事件日志 |
| `GET/POST/PATCH` profile 与 facts 接口 | 管理孩子档案和用户事实信息 |
| `GET /health` | 返回服务状态、注册 skill、模型 provider/model/enabled 状态 |

### 5.3 服务边界声明

1. 本服务输出为升学规划辅助建议，不替代教育主管部门、考试院、高校招生章程、学校官方通知或线下专业顾问的最终判断。
2. 涉及省份政策、院校专业组、录取分数、选科要求、报名条件等信息，应以当年本省考试院和高校官方发布为准。
3. 当前项目以结构化资产和本地知识库为支撑，未命中的具体院校、具体政策或具体路径，不应由模型自行猜测。
4. 对涉及未成年人教育规划的建议，应避免制造焦虑、歧视性判断或确定性承诺。

## 六、数据处理情况

### 6.1 数据类别

项目内 facts schema 和会话模型显示，服务可能处理以下数据：

| 数据类别 | 示例字段 | 用途 | 默认作用域 |
| --- | --- | --- | --- |
| 账号标识 | `user_id` | 区分家长/账号 | shared |
| 孩子档案标识 | `profile_id`、`profile_name` | 区分同一账号下多个孩子 | profile |
| 学业信息 | 年级、分数、最近三次大考均分、选科组合、成绩段位 | 升学分析、模拟升学、路径规划 | profile/session |
| 地区与政策相关信息 | 高考省份、所在地区/户籍地、户籍年限、学籍年限 | 判断省份规则和报考条件 | profile |
| 家庭约束 | 预算水平、家庭教育支持 | 多元路径和规划建议 | shared/profile |
| 特殊身份与兴趣 | 竞赛/特殊身份、职业兴趣、特长经历、兴趣标签 | 路径筛选、兴趣/特长诊断 | profile |
| 会话内容 | 用户输入、assistant 回复、message blocks | 上下文承接、问题答复、审计复盘 | session |
| 运行日志 | prompt assembly、retrieval details、events、snapshot | 调试、质量追踪、问题定位 | session/user |

### 6.2 Facts 生命周期

系统采用三层 facts 模型：

```text
effective_facts = shared_facts + profile_facts + session_facts
覆盖优先级：session > profile > shared
```

1. `shared_facts`：家庭共享信息，挂在 `user_id` 下。
2. `profile_facts`：孩子个体信息，挂在 `profile_id` 下。
3. `session_facts`：当前会话临时信息，挂在 `session_id` 下。
4. 后端在每轮对话前加载 facts，执行后保存上下文变更。

当前文件型存储位置：

| 数据 | 当前存储 |
| --- | --- |
| 用户 facts | `logs/users/{user_id}/facts.json` |
| 孩子档案 | `logs/users/{user_id}/profiles.json` |
| 孩子 facts | `logs/users/{user_id}/profiles/{profile_id}/facts.json` |
| 会话快照 | `logs/sessions/{session_id}/snapshot.json` |
| 会话事件 | `logs/sessions/{session_id}/events.jsonl` |

### 6.3 数据最小化与用户控制

当前代码已支持：

1. facts 分 scope 管理，减少跨场景重复采集。
2. 表单字段配置与 allowed values，控制采集字段范围。
3. facts reset、batch upsert、clear-by-source 等接口，支持修改和清理事实信息。
4. 按会话、用户、孩子档案维度记录来源，便于追溯信息从何处进入。


## 七、安全与合规措施

### 7.1 已在项目中体现的措施

| 措施 | 当前实现 |
| --- | --- |
| 权威上下文约束 | Prompt 明确要求以 Skill 指令、会话状态、本地资产和工具结果为权威上下文 |
| 资产支撑约束 | 未命中本地资产的具体路径、院校、省份政策或详细规划请求，要求使用 fallback 风格，不猜测 |
| 本地检索范围限制 | local RAG 读取范围限定为已加载 skill references 与 `assets/generated` |
| 输出引用清洗 | 默认隐藏引用文件名、reference 编号，避免暴露内部知识库路径 |
| 工具调用限制 | Skill Runtime 每轮工具调用上限，避免重复循环调用 |
| 路由稳定机制 | `LoopDefense` 通过置信度和连续命中轮次降低误切场景风险 |
| 事件审计 | 会话事件、prompt assembly、retrieval details、snapshot 可用于追溯 |
| 结构化 facts | 对关键事实字段设置 schema、scope、allowed values |
| 场景边界 | 选科、升学路径等 skill 明确“不得把未知条件当作确定结论” |


### 7.2 模型幻觉控制

当前已有的控制思路：

1. 结构化资产优先：模拟升学、多元路径、选科要求等场景优先用 JSON/Excel 编译资产。
2. 检索片段约束：本轮只使用匹配到的 references、local assets、generated assets。
3. fallback 约束：无资产支撑时不得臆测具体政策或结论。
4. 输出改写约束：提示词要求不能新增草稿中没有的事实、政策、数字、学校、路径规则、时间节点。


## 八、结论

本项目属于调用第三方大模型 API 构建的教育升学规划类生成式人工智能应用。项目的核心合规特征是：不自研基础模型、不在本地训练大模型，主要通过 Skill Runtime、结构化升学资产、facts 管理、检索增强、工具调用和提示词约束实现 Agent 应用能力。

当前代码已体现一定的安全边界，包括本地资产优先、未命中不猜测、输出引用清洗、工具调用限制、场景路由稳定、会话事件审计和 facts 分层管理。
